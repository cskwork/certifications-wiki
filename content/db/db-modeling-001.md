# 정규화 단계 (1NF~BCNF) — 각 단계 조건과 이상 현상

> 🔥 **매회 출제** (priority 3)

![[db-modeling-001.svg]]

## 🌱 왜 배우나

학생 정보와 수강 과목을 **한 테이블에** 몰아넣었다고 상상해 보자. 학생 이름이 바뀌면 그 학생의 수강 기록 모든 행을 다 고쳐야 하고(갱신 이상), 새 과목은 누군가 수강 신청을 해야만 등록되며(삽입 이상), 마지막 수강생이 취소하면 과목 자체가 사라진다(삭제 이상). 정규화는 이런 "한 테이블에 섞여 있어서 생기는 문제"를 **테이블을 쪼개서** 해결하는 설계 원칙이다. 마치 옷장을 정리할 때 상의·하의·속옷을 서랍별로 나누면 한 벌을 바꿔도 다른 옷들이 영향받지 않는 것과 같다.

## 📖 핵심 개념

정규화(Normalization)는 관계형 데이터베이스에서 데이터 중복을 최소화하고 **이상 현상(Anomaly)**을 제거하기 위해 릴레이션을 분해하는 과정이다. 핵심 아이디어는 "하나의 테이블에는 하나의 주제만 담는다"는 것. 이상 현상에는 삽입/삭제/갱신 이상 세 가지가 있고, 정규화 단계가 높아질수록 이상 현상이 줄어든다. 각 단계는 이전 단계를 만족한 상태에서 **함수 종속(Functional Dependency)** — 어떤 속성이 결정되면 다른 속성이 자동으로 결정되는 관계 — 를 기준으로 테이블을 추가로 분해한다. 1NF→2NF→3NF→BCNF→4NF→5NF 순서로 진행되며, 실무에서는 보통 **3NF 또는 BCNF까지** 정규화한다.

**핵심 용어**

- **제1정규형(1NF)**: 모든 속성의 도메인이 **원자값(Atomic Value)**만 포함 — 반복 그룹, 다중값 속성 제거
- **제2정규형(2NF)**: 1NF + **부분 함수 종속 제거** — 기본키의 일부 속성에만 종속되는 속성을 분리
- **제3정규형(3NF)**: 2NF + **이행 함수 종속 제거** — A→B, B→C일 때 A→C인 이행 종속을 분리
- **BCNF(Boyce-Codd NF)**: 3NF + **모든 결정자가 후보키** — 결정자이면서 후보키가 아닌 속성이 존재하면 위반
- **제4정규형(4NF)**: BCNF + **다치 종속(Multi-Valued Dependency) 제거** — 하나의 속성이 다른 두 독립 속성을 동시에 결정하는 경우 분리
- **제5정규형(5NF)**: 4NF + **조인 종속(Join Dependency) 제거** — 릴레이션을 분해한 뒤 재조인해도 원래 릴레이션을 복원할 수 있어야 함
- **이상 현상(Anomaly)**: 삽입 이상(원치 않는 데이터 강제 삽입), 삭제 이상(유용한 데이터 의도치 않은 삭제), 갱신 이상(일부만 수정 시 데이터 불일치)

## ✅ 이해 확인

1. 학생 테이블에 `(학번, 과목1, 과목2, 과목3)` 처럼 반복 컬럼이 있다면 위반하는 정규형은?
   <details><summary>정답</summary>제1정규형(1NF) — 원자값 원칙 위반. `(학번, 과목)`으로 행을 분해해야 한다.</details>
2. `(학번, 과목번호) → 성적`은 정상이지만 `학번 → 학생이름`이 성립하면 몇 정규형을 위반하는가?
   <details><summary>정답</summary>제2정규형(2NF) — 기본키 `(학번, 과목번호)`의 **일부**인 학번에만 종속되는 부분 함수 종속이다.</details>
3. BCNF는 3NF와 무엇이 다른가?
   <details><summary>정답</summary>3NF는 "비주요 속성"의 이행 종속만 제거하지만, BCNF는 **모든 결정자가 후보키**여야 한다. 즉 후보키가 아닌 속성이 다른 속성을 결정하는 경우까지 분해한다.</details>

## 🎯 시험 응용

> 정규화 단계 순서와 각 단계에서 제거하는 종속 유형을 정확히 구분해야 한다. 암기법: **"도부이결다조" (도메인 원자값 → 부분 함수 종속 → 이행 함수 종속 → 결정자 → 다치 종속 → 조인 종속)**. 시험에서는 "부분 함수 종속 제거 = 2NF", "이행 함수 종속 제거 = 3NF"를 묻는 문제가 가장 빈출된다.
