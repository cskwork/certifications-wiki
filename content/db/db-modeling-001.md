# 정규화 단계 (1NF~BCNF) — 각 단계 조건과 이상 현상

> 🔥 **매회 출제** (priority 3)

![[db-modeling-001.svg]]

## 🌱 왜 배우나

학생 이름, 전화번호, 수강 과목, 성적을 **한 표에** 몽땅 넣었다고 상상해 보자. 학생 이름이 바뀌면 그 학생이 들은 모든 과목 줄을 고쳐야 하고, 새 과목을 추가하려면 아직 아무도 수강하지 않았는데 가짜 학생을 넣어야 하고, 마지막 수강생이 취소하면 과목 정보 자체가 사라진다. 이런 문제를 이상 현상(Anomaly, 데이터를 넣거나·지우거나·고칠 때 생기는 의도치 않은 오류)이라고 부른다. 정규화(Normalization)는 "한 표에 여러 주제를 섞어서 생기는 문제"를 **표를 나눠서** 해결하는 설계 원칙이다. 옷장을 정리할 때 상의·하의·속옷을 서랍별로 나누면 한 벌을 바꿔도 다른 서랍이 영향받지 않는 것과 같다.

## 📖 핵심 개념

정규화(Normalization)란 관계형 데이터베이스(데이터를 표 형태로 저장하는 시스템)에서 데이터 중복을 줄이고 이상 현상을 없애기 위해 하나의 큰 표를 여러 작은 표로 쪼개는 과정이다. 핵심 원칙은 "하나의 표에는 하나의 주제만 담는다"이다. 이상 현상에는 세 가지가 있다. 삽입 이상(원하지 않는 데이터를 억지로 넣어야 함), 삭제 이상(지우면 안 될 데이터까지 함께 사라짐), 갱신 이상(일부만 고치면 데이터가 서로 안 맞게 됨). 각 정규화 단계는 이전 단계를 만족한 상태에서 함수 종속(Functional Dependency, FD — "학번을 알면 이름이 자동으로 정해진다"처럼 한 값이 다른 값을 결정하는 관계)을 기준으로 표를 추가로 나눈다. 단계는 1NF → 2NF → 3NF → BCNF(Boyce-Codd Normal Form) → 4NF → 5NF 순서로 진행하며, 실무에서는 보통 3NF 또는 BCNF까지 적용한다.

## 🔍 시각화

```
[비정규] ──▶ [1NF] ──▶ [2NF] ──▶ [3NF] ──▶ [BCNF]
              │          │          │          │
              ▼          ▼          ▼          ▼
          반복값 제거  부분종속    이행종속    모든 결정자
          (원자값만)   제거       제거       = 후보키

예시 흐름:
┌──────────────────────────────────────┐
│ 학번 │ 이름 │ 과목 │ 성적 │ 교수   │  ← 비정규 (한 표에 다 섞임)
└──────────────────────────────────────┘
                    ▼ 2NF 분해
┌───────────────┐  ┌──────────────────┐
│ 학번 │ 이름   │  │ 학번 │ 과목 │ 성적│  ← 학생 표 / 수강 표
└───────────────┘  └──────────────────┘
```

## ↔️ 이웃 개념 구분

- **정규화 vs 반정규화**: 정규화는 중복을 줄이려고 표를 쪼개는 것, 반정규화(Denormalization)는 성능을 높이려고 일부러 다시 합치는 것. 방향이 정반대다.
- **함수 종속 vs 다치 종속**: 함수 종속은 "A → B"(A가 정해지면 B가 딱 하나로 결정), 다치 종속(Multi-Valued Dependency, MVD)은 "A가 정해지면 B 값이 여러 개 나올 수 있는" 관계(4NF에서 제거).

**핵심 용어**

- **제1정규형(1NF, First Normal Form)**: 모든 칸에 값이 하나만 들어가야 한다(원자값). 한 칸에 "수학, 영어"처럼 여러 값을 넣으면 위반.
- **제2정규형(2NF, Second Normal Form)**: 1NF를 만족하면서, 기본키(Primary Key)의 일부에만 매달려 있는 속성을 분리한다(부분 함수 종속 제거).
- **제3정규형(3NF, Third Normal Form)**: 2NF를 만족하면서, A→B→C처럼 거쳐서 결정되는 관계를 분리한다(이행 함수 종속 제거).
- **BCNF(Boyce-Codd Normal Form)**: 3NF를 만족하면서, 다른 값을 결정하는 모든 속성(결정자)이 후보키여야 한다. 후보키가 아닌 속성이 결정자 역할을 하면 위반.
- **제4정규형(4NF)**: BCNF를 만족하면서, 다치 종속(MVD, Multi-Valued Dependency)을 제거.
- **제5정규형(5NF)**: 4NF를 만족하면서, 조인 종속(JD, Join Dependency — 표를 쪼갠 뒤 다시 합쳐도 원래와 같아야 하는 제약)을 제거.
- **이상 현상(Anomaly)**: 삽입 이상·삭제 이상·갱신 이상의 세 가지. 표 설계가 나쁠 때 발생하는 데이터 오류.

## ✅ 스스로 가르쳐보기

**질문**: 친구에게 "정규화가 왜 필요하고, 1NF부터 BCNF까지 단계별로 뭘 제거하는지" 3분 안에 설명해 보라.

체크포인트:
- [ ] 이상 현상 세 가지(삽입·삭제·갱신)를 각각 한 줄로 설명했는가?
- [ ] 각 단계에서 제거하는 종속 유형(원자값·부분·이행·결정자≠후보키)을 순서대로 말했는가?
- [ ] 함수 종속이 무엇인지 비유 없이 정의할 수 있는가?
- [ ] 3NF와 BCNF의 차이를 한 문장으로 구분했는가?

## 🎯 시험 응용

> 정규화 단계 순서와 각 단계에서 제거하는 종속 유형을 정확히 구분해야 한다. 암기법: **"도부이결다조" (도메인 원자값 → 부분 함수 종속 → 이행 함수 종속 → 결정자 → 다치 종속 → 조인 종속)**. 시험에서는 "부분 함수 종속 제거 = 2NF", "이행 함수 종속 제거 = 3NF"를 묻는 문제가 가장 빈출된다.
