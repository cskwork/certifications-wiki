# 릴레이션 구성 요소 (Tuple, Attribute, Domain, Degree, Cardinality)

> 🔥 **매회 출제** (priority 3)

![[db-relation-001.svg]]

## 🌱 왜 배우나

엑셀 시트를 떠올려 보자. 열(세로줄)이 몇 개인지, 행(가로줄)이 몇 개인지, "학년" 칸에는 1~4만 들어가야 한다는 규칙이 있다. 이 시트는 꽤 잘 정리된 것이다. 그런데 사람마다 "열 수"를 "필드 수"라고 부르기도 하고 "행 수"를 "레코드 수"라고 부르기도 한다면 대화가 뒤죽박죽이 된다. 관계형 데이터베이스(Relational Database, 데이터를 표 형태로 저장하는 시스템) 세계에서는 이 용어들을 하나로 통일해 놓았다. 그것이 Tuple(행), Attribute(열), Degree(열 개수), Cardinality(행 개수), Domain(값 범위)이다. 도서관에서 책 위치를 "3층 B서가 5번 칸"이라고 누구나 같은 말로 부르는 것과 같다.

## 📖 핵심 개념

릴레이션(Relation)이란 관계형 데이터베이스에서 데이터를 담는 2차원 표(테이블)를 가리키는 학술 용어다. 릴레이션은 다섯 가지 구성 요소로 설명된다. 가로 한 줄(행)을 튜플(Tuple)이라 하고, 세로 한 줄(열)을 속성(Attribute)이라 한다. 속성의 개수를 차수(Degree)라 하고, 튜플의 개수를 카디널리티(Cardinality)라 한다. 각 속성에 들어갈 수 있는 값의 범위를 도메인(Domain)이라 한다. 예를 들어 "학년" 속성의 도메인은 {1, 2, 3, 4}이다. 이 다섯 용어의 영문·한글 매핑과 개수 계산 방법이 시험 핵심이다.

## 🔍 시각화

```
릴레이션(테이블): 학생
┌────────┬────────┬────────┬────────┐
│  학번  │  이름  │  학과  │  학년  │ ← Attribute(속성) = 열
├────────┼────────┼────────┼────────┤
│ 1001   │ 김민수 │ 컴공   │ 2      │ ← Tuple(튜플) = 행
│ 1002   │ 이영희 │ 경영   │ 3      │
│ 1003   │ 박지훈 │ 컴공   │ 1      │
└────────┴────────┴────────┴────────┘

Degree(차수)      = 속성(열) 수 = 4
Cardinality(카디널리티) = 튜플(행) 수 = 3
Domain(도메인)    = 학년의 허용값 = {1, 2, 3, 4}
```

## ↔️ 이웃 개념 구분

- **Degree vs Cardinality**: Degree는 열(속성) 수, Cardinality는 행(튜플) 수. 가장 자주 헷갈리는 쌍이다.
- **Cardinality(릴레이션) vs Cardinality(ER 다이어그램)**: 릴레이션 문맥에서는 "행 수"를 뜻하고, ER 다이어그램(개체-관계 모델) 문맥에서는 "1:N, M:N 같은 관계 대응 수"를 뜻한다. 문제에서 대상이 표인지 관계인지를 먼저 확인해야 한다.

**핵심 용어**

- **Tuple(튜플)**: 릴레이션의 행(Row). 하나의 레코드(Record) 또는 인스턴스(Instance)에 해당한다.
- **Attribute(속성)**: 릴레이션의 열(Column). 필드(Field)라고도 부른다.
- **Domain(도메인)**: 각 속성이 가질 수 있는 값의 범위. 예: 학년 → {1, 2, 3, 4}.
- **Degree(차수)**: 릴레이션의 속성(열) 수.
- **Cardinality(카디널리티)**: 릴레이션의 튜플(행) 수.
- **Null**: 아직 값을 모르거나 적용할 수 없을 때 쓰는 표시. 숫자 0이나 빈 문자열과 다르다.
