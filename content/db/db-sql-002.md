# JOIN 종류 (INNER, LEFT, RIGHT, FULL OUTER, CROSS, SELF)

> 🔥 **매회 출제** (priority 3)

![[db-sql-002.svg]]

## 🌱 왜 배우나

정규화(표를 주제별로 나누는 설계 원칙)를 따르면 "학생 정보"와 "수강 정보"는 서로 다른 표에 저장된다. 그런데 성적표를 뽑으려면 "이 학번은 누구이고, 이 과목은 몇 점이었나"를 한 화면에 보여줘야 한다. 흩어진 정보를 다시 이어 붙이는 작업, 그것이 JOIN(조인, 두 개 이상의 표를 합치는 연산)이다. 쇼핑몰에서 "주문 번호"는 주문 장부에, "고객 이름"은 고객 명부에 따로 있지만 포장할 때는 두 장부를 맞춰서 "홍길동 고객의 1234번 주문"이라고 확인해야 하는 것과 같다. 조건과 일치 여부에 따라 결과가 달라지기 때문에 여러 종류의 JOIN을 구분해서 배운다.

## 📖 핵심 개념

JOIN은 두 개 이상의 표(테이블)를 공통 속성(조인 조건, 예: 두 표 모두에 있는 "학번" 열)을 기준으로 합쳐서 하나의 결과를 만드는 연산이다. 조인 조건에 따라 결과에 포함되는 행의 범위가 달라진다. INNER JOIN은 양쪽 모두 일치하는 행만, OUTER JOIN은 한쪽 또는 양쪽의 모든 행을 포함한다. 이를 통해 정규화로 나눈 표들의 관계를 다시 연결하여 원하는 정보를 조회할 수 있다.

## 🔍 시각화

```
표 A (학생)          표 B (수강)
┌────┬──────┐      ┌────┬──────┐
│학번│ 이름 │      │학번│ 과목 │
├────┼──────┤      ├────┼──────┤
│ 1  │ 김철 │      │ 1  │ 수학 │
│ 2  │ 이영 │      │ 1  │ 영어 │
│ 3  │ 박지 │      │ 4  │ 국어 │
└────┴──────┘      └────┴──────┘

INNER JOIN (학번 기준): 양쪽 다 있는 학번 1만
→ (1, 김철, 수학), (1, 김철, 영어)

LEFT JOIN (학생 기준): 학생 전부 + 일치하는 수강
→ (1, 김철, 수학), (1, 김철, 영어), (2, 이영, NULL), (3, 박지, NULL)

CROSS JOIN: 모든 조합 = 3 × 3 = 9행
```

## ↔️ 이웃 개념 구분

- **INNER JOIN vs LEFT JOIN**: INNER는 양쪽 다 일치하는 행만, LEFT는 왼쪽 표의 모든 행을 포함(일치 없으면 오른쪽이 NULL).
- **NATURAL JOIN vs EQUI JOIN**: NATURAL JOIN은 같은 이름의 열을 자동으로 조인 조건으로 사용하고, EQUI JOIN은 `=` 연산자를 명시적으로 쓰는 조인이다.

**핵심 용어**

- **INNER JOIN**: 양쪽 표에서 조인 조건이 일치하는 행만 반환한다. 교집합 개념.
- **LEFT (OUTER) JOIN**: 왼쪽 표의 모든 행을 유지하고, 오른쪽에서 일치하는 행을 붙인다. 일치 없으면 오른쪽은 NULL.
- **RIGHT (OUTER) JOIN**: 오른쪽 표의 모든 행을 유지하고, 왼쪽에서 일치하는 행을 붙인다. 일치 없으면 왼쪽은 NULL.
- **FULL OUTER JOIN**: 양쪽 표의 모든 행을 반환한다. 일치하지 않는 쪽은 NULL. 합집합 개념.
- **CROSS JOIN**: 조인 조건 없이 양쪽 표의 모든 행 조합을 만든다(카티션 곱, Cartesian Product). A 표 m행 × B 표 n행 = m×n행.
- **SELF JOIN**: 같은 표를 자기 자신과 조인한다. 별칭(Alias, 임시 이름)을 반드시 붙여 구분해야 한다. 예: 사원-관리자 관계 조회.

## ✅ 스스로 가르쳐보기

**질문**: 학생 표(5행)와 과목 표(4행)가 있을 때, INNER JOIN·LEFT JOIN·CROSS JOIN 각각의 결과 행 수가 어떻게 달라지는지 친구에게 설명해 보라.

체크포인트:
- [ ] INNER JOIN은 일치하는 행만 나온다고 말했는가?
- [ ] LEFT JOIN에서 일치 없는 행의 오른쪽이 NULL이 되는 이유를 설명했는가?
- [ ] CROSS JOIN 결과 행 수를 m×n으로 계산할 수 있는가?
- [ ] SELF JOIN에서 별칭이 필수인 이유를 말할 수 있는가?

## 🎯 시험 응용

> INNER JOIN과 OUTER JOIN의 차이, 특히 LEFT/RIGHT에서 NULL이 채워지는 위치를 정확히 이해해야 한다. CROSS JOIN의 결과 행 수(m*n)를 계산하는 문제가 출제된다. 또한 **자연 조인(NATURAL JOIN)**은 같은 이름의 속성을 자동으로 조인 조건으로 사용하며, **동등 조인(EQUI JOIN)**은 `=` 연산자를 사용하는 조인임을 구분할 것.
