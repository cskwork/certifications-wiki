### 🔥 정규화 단계 (1NF~BCNF) — 각 단계 조건과 이상 현상

![[db/db-modeling-001.svg]]

**핵심 개념**

정규화(Normalization)는 관계형 데이터베이스에서 데이터 중복을 최소화하고 **이상 현상(Anomaly)**을 제거하기 위해 릴레이션을 분해하는 과정이다. 이상 현상에는 삽입 이상, 삭제 이상, 갱신 이상이 있으며, 정규화 단계가 높아질수록 이상 현상이 줄어든다. 각 단계는 이전 단계를 만족한 상태에서 추가 조건을 적용한다.

**키워드**

- **제1정규형(1NF)**: 모든 속성의 도메인이 **원자값(Atomic Value)**만 포함 — 반복 그룹, 다중값 속성 제거
- **제2정규형(2NF)**: 1NF + **부분 함수 종속 제거** — 기본키의 일부 속성에만 종속되는 속성을 분리
- **제3정규형(3NF)**: 2NF + **이행 함수 종속 제거** — A→B, B→C일 때 A→C인 이행 종속을 분리
- **BCNF(Boyce-Codd NF)**: 3NF + **모든 결정자가 후보키** — 결정자이면서 후보키가 아닌 속성이 존재하면 위반
- **제4정규형(4NF)**: BCNF + **다치 종속(Multi-Valued Dependency) 제거** — 하나의 속성이 다른 두 독립 속성을 동시에 결정하는 경우 분리
- **제5정규형(5NF)**: 4NF + **조인 종속(Join Dependency) 제거** — 릴레이션을 분해한 뒤 재조인해도 원래 릴레이션을 복원할 수 있어야 함
- **이상 현상(Anomaly)**: 삽입 이상(원치 않는 데이터 강제 삽입), 삭제 이상(유용한 데이터 의도치 않은 삭제), 갱신 이상(일부만 수정 시 데이터 불일치)

> **🎯 기출 포인트** — 정규화 단계 순서와 각 단계에서 제거하는 종속 유형을 정확히 구분해야 한다. 암기법: **"도부이결다조" (도메인 원자값 → 부분 함수 종속 → 이행 함수 종속 → 결정자 → 다치 종속 → 조인 종속)**. 시험에서는 "부분 함수 종속 제거 = 2NF", "이행 함수 종속 제거 = 3NF"를 묻는 문제가 가장 빈출된다.

### 🔥 릴레이션 구성 요소 (Tuple, Attribute, Domain, Degree, Cardinality)

![[db/db-relation-001.svg]]

**핵심 개념**

관계형 데이터베이스에서 릴레이션(Relation)은 **2차원 테이블** 형태로 데이터를 저장한다. 릴레이션을 구성하는 각 요소의 정확한 영문 용어와 한글 용어를 매핑하고, 개수 계산 방법을 숙지하는 것이 시험 핵심이다.

**키워드**

- **Tuple(튜플)**: 릴레이션의 **행(Row)**, 하나의 레코드(Record)/인스턴스(Instance)에 해당. 개수 = **Cardinality(카디널리티)**
- **Attribute(속성)**: 릴레이션의 **열(Column)**, 필드(Field)에 해당. 개수 = **Degree(차수/디그리)**
- **Domain(도메인)**: 각 속성이 가질 수 있는 **값의 범위**. 예: 학년 속성의 도메인 = {1, 2, 3, 4}
- **Degree(차수)**: 릴레이션을 구성하는 **속성(컬럼)의 수**
- **Cardinality(카디널리티)**: 릴레이션에 저장된 **튜플(행)의 수**
- **Null**: 아직 알 수 없거나 적용 불가능한 값; 0이나 공백과 다름

> **🎯 기출 포인트** — 매회 1문제 이상 출제되는 최빈출 주제. **2024-2회**: Cardinality/Degree 값 계산 문제. **2025-1회**: degree, cardinality, foreign key, domain 용어 설명 매칭. **2025-2회**: Attribute 정의 문제. **2025-3회**: Tuple/Instance/Cardinality 용어 문제. 영문 Degree=속성 수, Cardinality=튜플 수를 반드시 암기할 것.

### 🔥 DDL 명령어 (CREATE, ALTER, DROP, TRUNCATE)

![[db/db-sql-001.svg]]

**핵심 개념**

DDL(Data Definition Language, 데이터 정의어)은 데이터베이스 **스키마(구조)**를 정의, 변경, 삭제하는 SQL 명령어 집합이다. DDL 명령어는 실행 즉시 **자동 커밋(Auto Commit)**되므로 ROLLBACK이 불가능하다. 대상은 테이블, 뷰, 인덱스, 스키마, 도메인 등이다.

**키워드**

- **CREATE**: 테이블, 뷰, 인덱스 등 객체 생성. `CREATE TABLE 학생 (학번 INT PRIMARY KEY, 이름 VARCHAR(20) NOT NULL);`
- **ALTER**: 기존 객체 구조 변경. `ADD`(컬럼 추가), `MODIFY`(컬럼 타입 변경), `DROP COLUMN`(컬럼 삭제), `RENAME`(이름 변경)
- **DROP**: 객체 완전 삭제(구조+데이터). `CASCADE`는 참조하는 모든 객체 함께 삭제, `RESTRICT`는 참조 객체 있으면 삭제 거부
- **TRUNCATE**: 테이블의 **모든 데이터만 삭제**(구조 유지). DROP과 달리 테이블 자체는 남으며, DELETE와 달리 로그를 남기지 않아 ROLLBACK 불가
- **제약조건**: PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK, DEFAULT — CREATE/ALTER 시 함께 정의

> **🎯 기출 포인트** — DDL vs DML vs DCL 분류가 단골 출제된다. **DDL = CREATE/ALTER/DROP/TRUNCATE**, **DML = SELECT/INSERT/UPDATE/DELETE**, **DCL = GRANT/REVOKE**. TRUNCATE는 DDL이므로 AUTO COMMIT 된다는 점, CASCADE/RESTRICT 옵션은 DROP에서 참조 무결성 처리 방식이라는 점을 구분할 것.

### 🔥 JOIN 종류 (INNER, LEFT, RIGHT, FULL OUTER, CROSS, SELF)

![[db/db-sql-002.svg]]

**핵심 개념**

JOIN은 두 개 이상의 테이블을 **공통 속성(조인 조건)**을 기준으로 결합하여 하나의 결과 집합을 생성하는 연산이다. 조인 조건에 따라 포함되는 행의 범위가 달라지며, 이를 통해 정규화로 분리된 테이블 간의 관계를 복원하여 조회할 수 있다.

**키워드**

- **INNER JOIN**: 양쪽 테이블에서 조인 조건이 **일치하는 행만** 반환. 가장 기본적인 조인 (교집합 개념)
- **LEFT (OUTER) JOIN**: 왼쪽 테이블의 **모든 행** + 오른쪽에서 일치하는 행 반환. 일치 없으면 오른쪽은 NULL
- **RIGHT (OUTER) JOIN**: 오른쪽 테이블의 **모든 행** + 왼쪽에서 일치하는 행 반환. 일치 없으면 왼쪽은 NULL
- **FULL OUTER JOIN**: 양쪽 테이블의 **모든 행** 반환. 일치하지 않는 행은 상대쪽이 NULL (합집합 개념)
- **CROSS JOIN**: 조인 조건 없이 양쪽 테이블의 **모든 행 조합**(카티션 곱). A테이블 m행 x B테이블 n행 = m*n행
- **SELF JOIN**: **같은 테이블**을 자기 자신과 조인. 별칭(Alias)을 사용하여 구분. 예: 사원-관리자 관계 조회

> **🎯 기출 포인트** — INNER JOIN과 OUTER JOIN의 차이, 특히 LEFT/RIGHT에서 NULL이 채워지는 위치를 정확히 이해해야 한다. CROSS JOIN의 결과 행 수(m*n)를 계산하는 문제가 출제된다. 또한 **자연 조인(NATURAL JOIN)**은 같은 이름의 속성을 자동으로 조인 조건으로 사용하며, **동등 조인(EQUI JOIN)**은 `=` 연산자를 사용하는 조인임을 구분할 것.

### 🔥 DML 명령어 (SELECT, INSERT, UPDATE, DELETE)

![[db/db-sql-003.svg]]

**핵심 개념**

DML(Data Manipulation Language, 데이터 조작어)은 테이블에 저장된 **데이터를 조회·삽입·수정·삭제**하는 SQL 명령어다. DDL과 달리 **자동 커밋되지 않으며** COMMIT/ROLLBACK으로 트랜잭션을 제어할 수 있다. SELECT 구문의 절 순서는 시험 단골 출제 포인트다.

**키워드**

- **SELECT 작성(문법) 순서**: `SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY` (순서 암기 필수)
- **SELECT 실행 순서**: `FROM → WHERE → GROUP BY → 집계함수 → HAVING → SELECT → ORDER BY` (작성 순서와 다름에 주의)
- **INSERT 두 가지 형태**: `INSERT INTO 테이블(컬럼) VALUES(값)` (직접 삽입) vs `INSERT INTO 테이블(컬럼) SELECT ... FROM ...` (조회 결과 삽입)
- **UPDATE**: `UPDATE 테이블 SET 컬럼=값 WHERE 조건` — WHERE 생략 시 전체 행 수정
- **DELETE**: `DELETE FROM 테이블 WHERE 조건` — WHERE 생략 시 전체 행 삭제 (TRUNCATE와 달리 ROLLBACK 가능, 로그 남김)
- **서브쿼리**: WHERE, FROM, SELECT 절에서 중첩 SELECT 사용 가능; 상관 서브쿼리는 외부 쿼리 행마다 실행

> **🎯 기출 포인트** — **2024-2회**: INSERT INTO...SELECT 구문에서 INSERT와 SELECT 키워드 빈칸 채우기로 출제됨. VALUES를 쓰는 단순 삽입과 SELECT를 쓰는 복사 삽입의 차이를 반드시 구분할 것. SELECT 절의 실행 순서(FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY)와 작성 순서를 혼동하지 말 것.

### 🔥 집계함수와 GROUP BY (COUNT, SUM, AVG, MAX, MIN, HAVING)

![[db/db-sql-004.svg]]

**핵심 개념**

집계함수(Aggregate Function)는 여러 행을 하나의 결과값으로 요약한다. **NULL 처리 규칙**이 함수마다 다르며 이 차이가 매회 출제된다. GROUP BY와 함께 사용하면 그룹별 집계가 가능하고, 그룹 조건 필터링은 WHERE가 아닌 **HAVING**을 사용해야 한다.

**키워드**

- **COUNT(\*)**: NULL을 포함한 **전체 행 수** 반환
- **COUNT(컬럼)**: 해당 컬럼에서 **NULL을 제외**한 행 수 반환
- **SUM / AVG / MAX / MIN**: 모두 NULL을 **자동 제외**하고 계산 (AVG는 NULL 제외 후 나눔)
- **GROUP BY**: 지정 컬럼의 값이 같은 행끼리 묶어 집계; SELECT에는 GROUP BY 컬럼 또는 집계함수만 올 수 있음
- **HAVING vs WHERE**: WHERE는 **그룹화 이전** 행 필터, HAVING은 **그룹화 이후** 집계 결과 필터
- **실행 순서**: FROM → WHERE → GROUP BY → 집계함수 적용 → HAVING → SELECT → ORDER BY

> **🎯 기출 포인트** — **2025-3회**: COUNT(*)와 COUNT(컬럼명)의 NULL 처리 차이 문제 출제. AVG 계산 시 NULL이 포함된 경우 분모가 달라지는 함정 주의. HAVING 절에서 집계함수를 조건으로 쓸 수 있지만 WHERE 절에서는 불가능하다는 점도 빈출 포인트.

### 🔥 OSI 7계층 모델

![[nw/nw-protocol-001.svg]]

**핵심 개념**

OSI(Open Systems Interconnection) 7계층 모델은 국제표준화기구(ISO)가 제정한 네트워크 통신의 표준 참조 모델이다. 통신 과정을 7개 계층으로 분리하여 각 계층이 독립적으로 기능을 수행하며, 계층 간 인터페이스를 통해 데이터를 전달한다. 각 계층은 고유한 PDU(Protocol Data Unit) 이름을 가진다.

**키워드**

- **물리 계층(L1)**: 비트(Bit) 전송. 전기적/기계적 신호 변환. 리피터, 허브. RS-232, X.21
- **데이터링크 계층(L2)**: 프레임(Frame) 단위 전송. 오류 검출/흐름 제어. 스위치, 브리지. HDLC, PPP, 이더넷
- **네트워크 계층(L3)**: 패킷(Packet) 라우팅. 논리 주소(IP) 지정. 라우터. IP, ICMP, ARP, OSPF, RIP
- **전송 계층(L4)**: 세그먼트(Segment) 단위. 종단 간(End-to-End) 신뢰성 보장. TCP, UDP. 포트 번호 사용
- **세션 계층(L5)**: 세션 관리(연결 설정/유지/해제). PDU: 데이터(Data). TLS(세션~표현 계층)
- **표현 계층(L6)**: 데이터 변환·암호화·압축. PDU: 데이터(Data). JPEG, MPEG, SSL/TLS
- **응용 계층(L7)**: 사용자 인터페이스 제공. PDU: 데이터(Data). HTTP, FTP, SMTP, DNS, SSH

> **🎯 기출 포인트** — 각 계층의 PDU 명칭(비트→프레임→패킷→세그먼트→데이터)은 빈칸 채우기로 빈출된다. 계층별 대표 프로토콜과 장비를 매칭하는 문제도 자주 출제된다. 특히 **ARP**(IP→MAC 변환, L3)와 **이더넷**(L2), **TCP/UDP**(L4)의 계층 위치를 정확히 구분해야 한다. 데이터 캡슐화(Encapsulation) 과정에서 각 계층이 헤더를 추가하는 순서도 중요하다.

### 🔥 응용 계층 프로토콜 (HTTP, HTTPS, FTP, SMTP, DNS, SNMP, SSH)

![[nw/nw-protocol-003.svg]]

**핵심 개념**

OSI 7계층 중 응용 계층(Layer 7)에 위치한 프로토콜들은 각각 고유한 포트 번호와 기능을 가진다. 정보처리기사 시험에서는 프로토콜 약어, 포트 번호, 역할의 매핑이 반드시 출제된다. 특히 SSH(22), HTTP(80), HTTPS(443), FTP(20/21), SMTP(25), DNS(53), SNMP(161) 조합은 핵심 암기 대상이다.

### 🔥 보안 공격 유형

![[nw/nw-security-001.svg]]

**핵심 개념**

네트워크 및 웹 보안 공격은 시스템의 가용성, 기밀성, 무결성을 위협하는 행위이다. 정보처리기사에서는 각 공격의 원리, 대상, 대응 방법을 구분할 수 있어야 한다. 공격 유형은 서비스 거부 공격, 인젝션 공격, 세션 탈취 공격, 네트워크 도청 등으로 분류된다.

**키워드**

- **DoS/DDoS**: 서비스 거부 공격. DoS는 단일 공격자가, DDoS는 다수의 좀비 PC(봇넷)가 대량 트래픽을 보내 서비스를 마비시킴. SYN Flood, Smurf, Land Attack, Ping of Death 등
- **SQL Injection**: 입력 필드에 악의적인 SQL 구문을 삽입하여 데이터베이스를 비정상적으로 조작. 대응: PreparedStatement(매개변수화 쿼리), 입력 값 검증
- **XSS(Cross-Site Scripting)**: 악성 스크립트를 웹 페이지에 삽입하여 다른 사용자의 브라우저에서 실행. 쿠키·세션 탈취. 대응: 입출력 값 이스케이프 처리, CSP 헤더
- **CSRF(Cross-Site Request Forgery)**: 인증된 사용자가 자신의 의지와 무관하게 공격자가 의도한 요청을 서버에 전송하게 만드는 공격. 대응: CSRF 토큰, Referer 검증
- **스니핑(Sniffing)**: 네트워크상의 패킷을 도청하여 정보를 수집. 대응: 암호화 통신(HTTPS, VPN), 스위칭 환경 사용

> **🎯 기출 포인트** — 각 공격 유형의 정의를 제시하고 공격 이름을 묻는 문제가 빈출된다. 특히 **SQL Injection**과 **XSS**의 차이(DB 조작 vs 브라우저 스크립트 실행), **DoS**와 **DDoS**의 차이(단일 vs 분산)를 명확히 구분해야 한다. DDoS 세부 공격인 **SYN Flood**(TCP 3-Way Handshake 악용, 대량 SYN 패킷 전송)와 **Smurf Attack**(ICMP 브로드캐스트 악용)도 서술형으로 출제된다.

### 🔥 네트워크 보안 공격 (SYN Flooding, Smurf, Watering Hole, 세션 하이재킹)

![[nw/nw-security-003.svg]]

**핵심 개념**

네트워크 보안 공격은 DoS/DDoS 계열(SYN Flooding, Smurf)과 세션/접근 탈취 계열(세션 하이재킹, Watering Hole)로 구분된다. 각 공격의 원리(어떤 취약점을 이용하는가)와 방어 방법이 시험 핵심이다. TCP 3-way handshake 취약점을 이용한 SYN Flooding은 가장 빈출 주제다.

**키워드**

- **원리**: TCP 3-way handshake 취약점 이용. 다수의 SYN 패킷을 위조된 IP로 전송 → 서버가 SYN-ACK을 보내도 ACK 미수신 → 서버의 백로그(backlog) 큐 고갈
- **분류**: DoS/DDoS 공격
- **방어**: SYN Cookie, 방화벽 필터링, 연결 임계값 설정
- **원리**: 출발지 IP를 피해자 IP로 위조 후, 브로드캐스트 주소로 ICMP Echo Request 전송 → 네트워크 내 모든 호스트가 피해자에게 Reply 집중
- **분류**: DDoS (증폭 공격, Amplification Attack)
- **방어**: 라우터에서 외부→내부 브로드캐스트 패킷 차단
- **원리**: 공격 대상이 자주 방문하는 웹사이트를 사전에 악성코드로 감염시켜 대기 → 피해자가 방문 시 자동 감염
- **분류**: 표적형 공격 (APT 계열)
- **방어**: 웹 브라우저/플러그인 최신 패치, 행위 기반 탐지
- **원리**: 합법적인 사용자의 인증된 세션 ID를 탈취하여 해당 세션에 무단 참여
- **취약점**: TCP 시퀀스 번호 예측, 세션 ID 스니핑
- **방어**: HTTPS 사용, 세션 ID 재생성(로그인 후), HttpOnly/Secure 쿠키 속성

> **🎯 기출 포인트** — **2025-2회**: SYN Flooding 공격 원리 출제 — "TCP 3-way handshake 취약점 이용" > **2025-1회**: 세션 하이재킹 출제 — "인증된 세션을 가로채는 공격" > **2024-1회**: Watering Hole 출제 — "자주 방문하는 사이트를 감염시켜 대기" > **2024-3회**: Smurf 공격 출제 — "브로드캐스트 주소를 이용한 증폭 DDoS"

### 🔥 CPU 스케줄링 알고리즘 (FCFS, SJF, SRT, RR, 우선순위)

![[os/mt-scheduling-001.svg]]

**핵심 개념**

CPU 스케줄링은 준비 큐에 있는 프로세스 중 어떤 프로세스에 CPU를 할당할지 결정하는 알고리즘이다. **선점(Preemptive)** 방식은 실행 중인 프로세스를 강제로 중단시킬 수 있고, **비선점(Non-preemptive)** 방식은 프로세스가 자발적으로 CPU를 반납할 때까지 기다린다. 평균 대기시간과 평균 반환시간 계산이 핵심 출제 포인트이다.

**키워드**

- **도착시간(Arrival Time)**: 프로세스가 준비 큐에 도착한 시간
- **버스트 시간(Burst Time)**: CPU를 사용하는 시간
- **완료시간(Completion Time)**: 프로세스 실행 완료 시간
- **반환시간(Turnaround Time)** = 완료시간 - 도착시간
- **대기시간(Waiting Time)** = 반환시간 - 버스트시간

> **🎯 기출 포인트** — **2025-2회**: SJF/SRT 비교 + 라운드 로빈 타임퀀텀=3일 때 평균 반환시간 11.75ms 계산 문제 출제. > **2025-2회**: 라운드 로빈에서 타임퀀텀이 클수록 FCFS에 가까워지고, 작을수록 문맥교환 오버헤드 증가. > **2024-2회**: SRT 평균 대기시간 6.5ms 계산 문제 — 각 타임슬롯마다 남은 버스트시간 재계산 필수. > 계산 문제는 **간트 차트(Gantt Chart)**를 직접 그리며 타임라인을 시각화하면 오류 방지.

### 🔥 소프트웨어 테스트 기법 — 화이트박스 vs 블랙박스

![[os/mt-testing-001.svg]]

**핵심 개념**

소프트웨어 테스트 기법은 내부 구조를 기반으로 하는 화이트박스 테스트와 외부 기능 명세를 기반으로 하는 블랙박스 테스트로 구분된다. 화이트박스는 코드 로직의 커버리지를 높이는 데 초점을 맞추고, 블랙박스는 요구사항 대비 기능의 정확성을 검증한다.

**키워드**

- **화이트박스 테스트(구조적)**: 내부 소스 코드 로직 기반. **구문 커버리지**(모든 문장 실행), **결정 커버리지**(=분기 커버리지, 모든 분기 실행), **조건 커버리지**(모든 조건식 T/F 실행), **경로 커버리지**(모든 가능한 경로 실행), **조건/결정 커버리지**, **변경 조건/결정 커버리지(MC/DC)**
- **블랙박스 테스트(기능적)**: 외부 명세 기반, 내부 구조 무관. **동치 분할**(유효/무효 입력 클래스 분할), **경계값 분석**(경계 부근 값 테스트), **원인-결과 그래프**, **의사결정 테이블**, **상태 전이 테스트**, **유스케이스 테스트**
- **커버리지 강도 순서**: 구문 < 결정(분기) < 조건 < 조건/결정 < MC/DC < 경로 (경로 커버리지가 가장 강력). 주의: 조건 커버리지가 반드시 분기 커버리지를 포함하지는 않음 — 조건 T/F를 모두 실행해도 전체 조건식의 T/F가 모두 나오지 않을 수 있음
- **경험 기반 테스트**: 오류 추정(Error Guessing), 탐색적 테스트(Exploratory Testing). 테스터의 경험과 직관에 의존
- **검증(Verification) vs 확인(Validation)**: 검증은 "올바르게 만들고 있는가"(개발 과정), 확인은 "올바른 것을 만들었는가"(사용자 요구 충족)

> **🎯 기출 포인트** — **화이트박스 기법과 블랙박스 기법의 분류** 문제가 매우 빈출된다. 동치 분할, 경계값 분석은 블랙박스, 구문/결정/조건/경로 커버리지는 화이트박스임을 반드시 구분해야 한다. **커버리지 강도 순서**와 각 커버리지의 정의를 서술하는 문제도 출제된다. 검증(Verification)과 확인(Validation)의 차이도 빈칸 채우기로 자주 나온다.

### 🔥 테스트 커버리지 (문장, 분기, 조건, MC/DC, 경로)

![[os/mt-testing-003.svg]]

**핵심 개념**

테스트 커버리지(Test Coverage)는 테스트가 소스 코드의 어느 부분을 실행했는지를 측정하는 지표이다. 커버리지 기준이 엄격할수록 더 많은 테스트 케이스가 필요하며, 강도 순서는 **문장 < 분기 < 조건 < MC/DC < 경로** 순이다. 높은 커버리지가 높은 품질을 보장하지는 않지만, 테스트 충분성의 기준으로 활용된다.

**키워드**

- **문장 커버리지(Statement Coverage)**: 모든 실행 가능한 문장을 최소 1회 실행 — 가장 약한 기준
- **분기 커버리지(Branch Coverage)**: 모든 조건문의 참(T)/거짓(F) 분기를 모두 실행 — Decision Coverage라고도 함
- **조건 커버리지(Condition Coverage)**: 각 조건(개별 Boolean 표현식)이 T/F를 모두 취하도록 실행
- **MC/DC(Modified Condition/Decision Coverage)**: 각 개별 조건이 독립적으로 결정(Decision)에 영향을 미치는 경우를 테스트 — 항공 소프트웨어 표준(DO-178C)에서 요구
- **경로 커버리지(Path Coverage)**: 모든 가능한 실행 경로를 실행 — 가장 강한 기준이나 경우의 수 폭발로 실현 불가능한 경우 多

> **🎯 기출 포인트** — **2025-2회**: `if (A && B)` 조건에서 분기 커버리지와 조건 커버리지의 테스트 케이스 수 비교 문제 출제. 분기 커버리지는 전체 조건식의 T/F → 최소 2개(예: A=T,B=T / A=F,B=F). 조건 커버리지는 개별 조건 A, B 각각 T/F → 최소 2개이나 분기를 보장하지 않을 수 있음. 단락평가(Short-circuit) 시 A=F이면 B 미평가. > **2025-3회**: 조건 커버리지 정의와 분기 커버리지의 차이점 서술 문제 출제. > 분기 커버리지는 **조건식 전체**의 T/F를 다루고, 조건 커버리지는 **개별 조건**의 T/F를 다룬다는 차이를 반드시 구분할 것. > MC/DC는 분기+조건 커버리지를 만족하면서 조건 간 독립성까지 보장한다.

### 🔥 연결 리스트

![[pg/pg-data-structure-002.svg]]

**핵심 개념**

연결 리스트(Linked List)는 노드(데이터 + 포인터)를 동적으로 연결한 자료구조다. 배열과 달리 메모리가 연속적이지 않아 삽입/삭제가 O(1)이지만, 임의 접근은 O(n)이다. 기출에서는 주로 C 구조체 포인터를 이용한 코드를 주고 순회 결과를 추적하는 형식으로 출제된다.

**키워드**

- **노드(Node)**: data 필드 + next 포인터(단일) 또는 prev/next 포인터(이중)
- **head**: 첫 번째 노드를 가리키는 포인터. 리스트의 시작점
- **->**: 포인터로 구조체 멤버 접근 연산자. `p->data` == `(*p).data`
- **단일 연결 리스트**: 한 방향(next)으로만 순회 가능
- **이중 연결 리스트**: prev/next 양방향 순회 가능
- **원형 연결 리스트**: 마지막 노드의 next가 head를 가리킴

### 🔥 C언어 포인터 기초

![[pg/pg-language-001.svg]]

**핵심 개념**

포인터(Pointer)는 **메모리 주소를 저장하는 변수**이다. 선언 시 `*` 기호를 사용하며, 변수의 주소를 얻을 때는 주소 연산자 `&`를, 포인터가 가리키는 값에 접근할 때는 역참조 연산자 `*`를 사용한다. 포인터를 통해 변수의 값을 간접적으로 읽거나 수정할 수 있다.

**키워드**

- **포인터 선언**: `int *p;` (정수형 포인터 변수 p 선언, 아직 어떤 주소도 가리키지 않음)
- **주소 연산자(&)**: `p = &a;` (변수 a의 메모리 주소를 포인터 p에 저장)
- **역참조 연산자(*)**: `*p` (포인터 p가 가리키는 주소에 저장된 값에 접근)
- **포인터와 배열**: 배열명은 첫 번째 원소의 주소를 나타내는 포인터 상수. `arr[i]`는 `*(arr+i)`와 동일
- **NULL 포인터**: 아무것도 가리키지 않는 포인터. 초기화되지 않은 포인터 사용 시 오류 발생 가능

> **🎯 기출 포인트** — C언어 포인터 문제는 실기 단골 출제 유형이다. `&`(주소 연산자)와 `*`(역참조 연산자)의 역할을 반드시 구분할 것. 포인터를 이용한 **값 교환(swap)** 문제, 포인터와 배열의 관계(`*(arr+i)` == `arr[i]`), 이중 포인터(`**pp`)를 활용한 출력 결과 추적 문제가 빈출된다. 코드 트레이싱 시 변수의 주소와 값을 표로 정리하면 실수를 줄일 수 있다.

### 🔥 Java 상속과 오버라이딩

**키워드**

- **extends**: 클래스 상속 선언 키워드. Java는 단일 상속만 허용
- **super()**: 부모 클래스 생성자 호출. 자식 생성자의 첫 줄에서만 사용 가능

- **정적 바인딩**: 컴파일 타임에 참조 변수 타입으로 결정 (static 메서드, 필드)

### 🔥 C언어 재귀 함수

![[pg/pg-language-008.svg]]

**핵심 개념**

재귀 함수(Recursive Function)는 **자기 자신을 호출하는 함수**이다. 반드시 종료 조건(Base Case)이 필요하며, 호출될 때마다 스택 프레임이 쌓인다. 코드 추적 시 호출 트리를 그려서 반환값을 역추적하는 것이 핵심이다.

**키워드**

- **종료 조건(Base Case)**: 재귀 호출을 멈추는 조건. 없으면 무한 재귀 → 스택 오버플로우

- **꼬리 재귀(Tail Recursion)**: 재귀 호출이 함수의 마지막 연산인 경우

> **🎯 기출 포인트** — - **2025-1회**: Java 재귀함수 결과 추적 (답: 20). C와 동일한 트레이싱 기법 적용 > - **매회 1~2문항**: 재귀 함수 출력 결과 쓰기는 가장 빈출되는 유형 > - **트레이싱 팁**: 호출 트리를 그려서 종료 조건부터 역으로 계산하면 정확도 향상 > - **주의**: `f(n-1) + f(n-2)` 같은 이중 재귀는 호출 횟수가 기하급수적 증가

### 🔥 Java 예외처리 try-catch-finally

![[pg/pg-language-011.svg]]

**핵심 개념**

- **throw**: 예외를 명시적으로 발생시킴

### 🔥 Java String 메서드

![[pg/pg-language-014.svg]]

**핵심 개념**

Java의 String은 **불변 객체(Immutable)**로, 문자열 조작 메서드는 원본을 변경하지 않고 **새로운 String을 반환**한다. substring, charAt, length 등의 메서드로 문자열을 다루며, 인덱스가 0부터 시작한다는 점이 코드 추적의 핵심이다.

**키워드**

- **length()**: 문자열 길이 반환. `"abc".length()` → 3
- **charAt(index)**: 해당 인덱스의 문자 반환. `"abc".charAt(1)` → 'b'
- **substring(start, end)**: start부터 end-1까지 부분 문자열. `"abcde".substring(1,4)` → "bcd"
- **substring(start)**: start부터 끝까지. `"abcde".substring(2)` → "cde"
- **indexOf(str)**: str이 처음 나타나는 인덱스. 없으면 -1
- **toUpperCase() / toLowerCase()**: 대소문자 변환
- **replace(old, new)**: 문자/문자열 치환
- **split(regex)**: 구분자로 분리하여 String 배열 반환
- **trim()**: 양쪽 공백 제거
- **equals(str)**: 문자열 내용 비교 (`==`는 참조 비교)

> **🎯 기출 포인트** — - **매회 출제**: String 메서드를 활용한 출력 결과 추적은 단골 문제 > - **출제 패턴**: substring 범위 계산, charAt 인덱스, length/indexOf 반환값 > - **핵심**: substring(start, end)에서 **end 인덱스는 미포함** > - **주의**: `==`는 참조 비교, `equals()`는 내용 비교. 시험에서 자주 함정으로 출제

### 🔥 Python 문자열 메서드

![[pg/pg-language-017.svg]]

**핵심 개념**

Python 문자열은 **불변(immutable)**이며, 모든 문자열 메서드는 원본을 변경하지 않고 **새로운 문자열을 반환**한다. split, join, replace는 가장 빈출되는 메서드이며, 메서드 체인으로 연속 호출하는 출력 추적이 핵심이다.

**키워드**

- **split(구분자)**: 구분자로 분리 → 리스트 반환. `"a,b,c".split(",")` → `['a','b','c']`
- **join(리스트)**: 리스트를 구분자로 결합. `"-".join(['a','b'])` → `"a-b"`
- **replace(old, new)**: 모든 old를 new로 치환. `"aab".replace("a","x")` → `"xxb"`
- **find(str)**: str의 첫 번째 인덱스 반환. 없으면 -1
- **upper() / lower()**: 대소문자 변환
- **strip()**: 양쪽 공백 제거 (lstrip, rstrip은 한쪽만)
- **count(str)**: str의 등장 횟수
- **startswith(str) / endswith(str)**: 접두사/접미사 확인 (bool)

> **🎯 기출 포인트** — - **매회 출제**: split → join → replace 등 메서드 체인 결과 추적 > - **출제 패턴**: 문자열 조작 후 출력값 쓰기. 인덱싱/슬라이싱과 혼합 출제 > - **핵심**: split은 리스트 반환, join은 문자열 반환. 반환 타입에 주의 > - **주의**: replace는 **모든** 매칭을 치환 (첫 번째만이 아님)

### 🔥 모듈 응집도 7단계

![[se/se-cohesion-001.svg]]

**핵심 개념**

응집도(Cohesion)는 모듈 내부 구성 요소들이 하나의 목적을 위해 얼마나 밀접하게 관련되어 있는가를 나타낸다. 높을수록(강할수록) 좋은 설계이며, 결합도와 반대 방향으로 이해한다. 7단계를 강→약 순서로 암기하고 각 유형의 정의를 구별하는 것이 핵심이다.

**키워드**

- **Functional(기능적) 응집도** [최강]: 모듈 내 모든 요소가 단일 기능 수행에 기여 — 가장 이상적
- **Sequential(순차적) 응집도**: 한 활동의 출력이 다음 활동의 입력으로 연결 — 파이프라인 구조
- **Communication(통신적) 응집도**: 동일한 입력/출력 데이터를 사용하는 활동들의 집합 — 같은 데이터 처리
- **Procedural(절차적) 응집도**: 특정 순서에 따라 수행되어야 하는 활동들의 집합 — 순서 중요, 데이터 무관
- **Temporal(시간적) 응집도**: 특정 시간대에 함께 실행되는 기능들의 집합 — 초기화 루틴, 종료 루틴
- **Logical(논리적) 응집도**: 유사한 성격이나 범주에 속하는 기능들을 하나의 모듈로 묶음 — 제어 플래그로 선택
- **Coincidental(우연적) 응집도** [최약]: 관련 없는 기능들이 우연히 같은 모듈에 존재 — 최악의 설계

> **🎯 기출 포인트** — - **강→약 순서 암기법**: "기순통절시논우" (기능-순차-통신-절차-시간-논리-우연) > - **2024-2회**: 순차적 응집도 정의 빈칸 문제 — "한 활동의 출력이 다음 활동의 입력" > - 순차(Sequential) vs 절차(Procedural) 혼동 주의: 순차는 데이터 흐름, 절차는 실행 순서 > - 응집도는 높을수록 / 결합도는 낮을수록 좋은 설계 — 반드시 함께 암기

### 🔥 모듈 결합도 6단계

![[se/se-coupling-001.svg]]

**핵심 개념**

결합도(Coupling)는 모듈 간의 상호 의존 정도를 나타내며, 낮을수록(약할수록) 좋은 설계다. 결합도가 낮으면 모듈의 독립성이 높아져 유지보수와 재사용이 용이해진다. 6단계를 강→약 순서로 암기하고 각 유형의 정의를 구별하는 것이 핵심이다.

**키워드**

- **Content(내용) 결합도** [최강]: 다른 모듈의 내부 데이터나 코드를 직접 참조·수정 — 최악의 결합
- **Common(공통) 결합도**: 두 모듈이 전역 변수(공통 데이터)를 공유 — 전역 변수 사용
- **External(외부) 결합도**: 외부에서 선언된 변수(외부 데이터 포맷, 프로토콜 등)를 공유 — 공통과 유사하나 외부 환경
- **Control(제어) 결합도**: 한 모듈이 다른 모듈의 제어 흐름(논리적 경로)을 결정하는 파라미터 전달 — 제어 플래그
- **Stamp(스탬프) 결합도**: 모듈 간에 자료 구조(레코드·배열 등)를 파라미터로 전달, 일부만 사용 — 구조체 전달
- **Data(자료) 결합도** [최약]: 모듈 간에 단순 값(스칼라) 파라미터만 전달 — 최선의 결합

> **🎯 기출 포인트** — - **강→약 순서 암기법**: "내공외제스자" (내용-공통-외부-제어-스탬프-자료) > - **2025-1회**: 내용·스탬프·공통 결합도 정의 구분 문제 출제 > - **2024-2회**: 제어 결합도 — 제어 플래그를 파라미터로 전달하는 유형 > - "전역 변수 = 공통 결합도", "제어 플래그 파라미터 = 제어 결합도" 키워드 연결 필수

### 🔥 디자인패턴 - GoF 생성패턴 5가지

![[se/se-design-001.svg]]

**핵심 개념**

GoF(Gang of Four) 디자인패턴은 생성(Creational), 구조(Structural), 행위(Behavioral) 3가지로 분류된다. **생성패턴**은 객체 생성 메커니즘을 다루며, 시스템이 어떤 구체 클래스를 사용하는지 감추고 객체 생성의 유연성을 높인다. 생성패턴 5가지는 암기 필수 항목이다.

**키워드**

- **Abstract Factory**: 관련된 객체군(family)을 생성하는 인터페이스 제공. 구체 팩토리를 교체하면 제품군 전체가 바뀜
- **Builder**: 복잡한 객체의 생성 과정과 표현을 분리. 동일한 생성 절차로 다른 표현 결과를 만듦
- **Factory Method**: 객체 생성을 서브클래스에 위임. 상위 클래스는 인터페이스만 정의하고 하위 클래스가 구체 클래스를 결정
- **Prototype**: 기존 객체를 복제(clone)하여 새 객체를 생성. 생성 비용이 클 때 유용
- **Singleton**: 클래스의 인스턴스를 하나만 생성하고 전역 접근점을 제공

> **🎯 기출 포인트** — 암기법: **"AB를 FPS로 만든다"** (Abstract Factory, Builder, Factory Method, Prototype, Singleton). 생성패턴은 총 5개, 구조패턴 7개(어댑터, 브리지, 컴포지트, 데코레이터, 퍼사드, 플라이웨이트, 프록시), 행위패턴 11개이다. 패턴 이름과 분류를 정확히 매칭하는 문제가 자주 출제된다.

### 🔥 GoF 구조 패턴 7가지

![[se/se-design-002.svg]]

**핵심 개념**

구조 패턴은 클래스나 객체를 조합하여 더 큰 구조를 만드는 패턴이다. 인터페이스 호환, 기능 확장, 접근 제어, 복잡성 은닉 등의 목적으로 사용된다. 7가지 패턴 각각의 목적과 구조의 차이를 명확히 구분하는 것이 시험의 핵심이다.

**키워드**

- **Adapter(어댑터)**: 호환되지 않는 인터페이스를 연결 — "변환기", 기존 클래스를 수정 없이 재사용
- **Proxy(프록시)**: 실제 객체 대신 대리 객체를 통해 접근 제어 — "대리인", 보안·캐싱·지연 로딩에 활용
- **Bridge(브리지)**: 추상화와 구현을 분리하여 독립적으로 확장 — "분리", 구현부와 기능부를 별도 계층으로
- **Decorator(데코레이터)**: 객체에 동적으로 새로운 기능 추가 — "포장지", 상속 없이 기능 확장
- **Facade(파사드)**: 복잡한 서브시스템에 단순한 인터페이스 제공 — "창구", 서브시스템 의존성 감소
- **Composite(컴포지트)**: 개별 객체와 복합 객체를 동일하게 취급 — "트리구조", 파일/폴더 계층 구현
- **Flyweight(플라이웨이트)**: 공유를 통해 다수의 유사 객체를 효율적으로 지원 — "메모리 절약", 공유 상태(intrinsic) 분리

> **🎯 기출 포인트** — - **2025-1회**: Adapter 패턴 — 기존 클래스의 인터페이스를 클라이언트가 원하는 형태로 변환하는 패턴 > - **2025-2회**: Proxy 패턴 — 다른 객체에 대한 접근을 제어하기 위한 대리자를 제공하는 패턴 > - **2024-2회**: Iterator 패턴 출제 — **Iterator는 행위 패턴**이므로 구조 패턴과 혼동하지 말 것. 구조 패턴 중 가장 빈출은 Adapter와 Proxy > - 패턴명 영문 표기 + 한글 목적 한 줄 요약을 함께 암기할 것

### 🔥 GoF 행위 패턴 11가지

![[se/se-design-003.svg]]

**핵심 개념**

행위 패턴은 객체나 클래스 간의 알고리즘 및 책임 분배에 관한 패턴이다. 객체 간 통신 방식, 알고리즘 캡슐화, 상태 관리 등을 다루며 GoF 3가지 분류 중 패턴 수가 가장 많다(11가지). 시험에서 비중이 가장 높은 분류다.

**키워드**

- **Observer(옵저버)**: 객체 상태 변화 시 의존 객체들에 자동 통지 — "이벤트 구독", 1:N 의존 관계
- **Strategy(전략)**: 알고리즘을 캡슐화하여 교체 가능하게 — "전략 교체", 런타임에 알고리즘 변경
- **Command(커맨드)**: 요청을 객체로 캡슐화하여 실행 취소·재실행 지원 — "명령 객체화"
- **Iterator(이터레이터)**: 컬렉션 내부 구조 노출 없이 순차 접근 — "순회", 내부 표현 독립적 접근
- **State(상태)**: 객체 상태에 따라 행동을 변경 — "상태 기계", 상태별 클래스로 분리
- **Template Method(템플릿 메서드)**: 알고리즘 골격을 상위 클래스에 정의, 세부 구현은 하위 클래스에 위임
- **Visitor(방문자)**: 객체 구조와 연산을 분리하여 새 연산을 쉽게 추가 — "이중 디스패치"
- **Mediator(중재자)**: 객체 간 통신을 중재 객체가 담당 — "통신 집중화", 결합도 감소
- **Memento(메멘토)**: 객체 상태를 외부에 저장하여 이전 상태로 복원 — "스냅샷", Undo 구현
- **Chain of Responsibility(책임 연쇄)**: 요청을 처리할 수 있는 객체를 연쇄적으로 탐색 — "체인"
- **Interpreter(인터프리터)**: 언어의 문법을 클래스로 표현하고 인터프리터 구현

> **🎯 기출 포인트** — - 빈출 Top 3: **Iterator**, **Observer**, **Strategy** — 매회 출제 수준 > - **2024-2회**: Iterator 패턴 설명 빈칸 문제 출제 > - 구조 패턴 Facade와 혼동 주의 — Facade는 구조 패턴, State·Strategy는 행위 패턴 > - "알고리즘 교체" → Strategy, "상태에 따른 행동 변화" → State 구분 필수

### 🔥 UML 다이어그램 종류 (구조/행위 분류)

![[se/se-requirements-001.svg]]

**핵심 개념**

UML(Unified Modeling Language) 다이어그램은 크게 **구조 다이어그램(Structural)**과 **행위 다이어그램(Behavioral)**으로 분류된다. 구조 다이어그램은 시스템의 정적인 구조를 표현하고, 행위 다이어그램은 시스템의 동적인 동작과 상호작용을 표현한다.

**키워드**

- **구조 다이어그램 (7종, UML 2.5 기준)**: 클래스, 객체, 컴포넌트, 배치(Deployment), 복합구조, 패키지, 프로파일 다이어그램 (일부 수험서는 프로파일 제외 6종으로 기술)
- **행위 다이어그램 (7종)**: 유스케이스, 시퀀스, 커뮤니케이션, 상태, 활동, 상호작용 개요, 타이밍 다이어그램
- **상호작용 다이어그램**: 행위 다이어그램의 하위 분류로 시퀀스, 커뮤니케이션, 상호작용 개요, 타이밍이 포함됨
- **유스케이스 다이어그램**: 사용자(액터)와 시스템 간의 상호작용을 표현하는 행위 다이어그램

> **🎯 기출 포인트** — 시퀀스, 커뮤니케이션, 활동, 상태, 유스케이스는 행위 다이어그램이다. 클래스, 객체, 컴포넌트, 배치는 구조 다이어그램이다. 특히 "배치 다이어그램"을 행위로 혼동하는 경우가 많으므로 주의할 것. 암기법: **구조 = 정적(무엇이 있는가)**, **행위 = 동적(어떻게 동작하는가)**.
