# Java 상속과 오버라이딩

> 🔥 **매회 출제** (priority 3)

![[pg-language-003.svg]]

## 🌱 왜 배우나

Dog, Cat, Cow, Bird 클래스(객체를 찍어내는 설계도)를 각각 만든다고 하자. "이름, 나이, 먹기, 걷기" 같은 공통 속성과 동작을 매번 복사해서 붙여야 한다. 중복이 귀찮을 뿐 아니라 나중에 공통 부분을 고치려면 모든 클래스를 다 찾아서 수정해야 한다.

상속은 "공통 부분을 하나의 부모(Animal)에 모아 두고, 자식(Dog, Cat …)은 부모의 것을 물려받되 자기만의 특성만 새로 정의하자"는 아이디어다. 부모의 설계도를 물려받으면서 필요한 부분만 덮어쓸 수 있게 하려고 `extends`(상속)와 `@Override`(덮어쓰기)가 등장했다.

## 📖 핵심 개념

상속(Inheritance)은 부모 클래스의 변수와 메서드(기능)를 자식 클래스가 물려받는 방법이다. `extends` 키워드(예약어)로 선언한다. 오버라이딩(Overriding)은 부모에게 물려받은 메서드를 자식이 자기 방식대로 다시 정의하는 것이다. `@Override` 표시를 붙이면 컴파일러(코드를 실행 파일로 바꿔주는 도구)가 시그니처(메서드 이름, 매개변수 등)가 맞는지 확인해 준다. 인스턴스 메서드(객체에 속한 일반 메서드)는 동적 바인딩(실행 시점에 실제 객체 타입에 따라 어떤 메서드를 호출할지 결정하는 방식)을 따른다. 반면 static 메서드(클래스에 속한 메서드)와 필드(변수)는 정적 바인딩(코드를 해석하는 시점에 참조 변수의 타입으로 결정하는 방식)을 따른다.

## 🔍 시각화

```
상속 구조:

┌─────────────┐
│   Animal    │  ← 부모 클래스
│ sound(): "…"│
│ speak()     │
└──────┬──────┘
       │ extends (물려받기)
       ▼
┌─────────────┐
│    Dog      │  ← 자식 클래스
│ sound(): "멍멍"│  ← @Override (덮어쓰기)
└─────────────┘

동적 바인딩 흐름:

  Animal a = new Dog();
  a.speak();

  speak() 내부에서 sound() 호출
       │
       ▼
  a의 실제 타입은 Dog
       │
       ▼
  Dog의 sound() 실행 → "멍멍"
```

## ↔️ 이웃 개념 구분

- **오버라이딩(Overriding) vs 오버로딩(Overloading)**: 오버라이딩은 부모의 같은 메서드를 자식이 재정의, 오버로딩은 같은 이름의 메서드를 매개변수만 다르게 여러 개 만드는 것.
- **동적 바인딩 vs 정적 바인딩**: 인스턴스 메서드는 실제 객체 타입으로 결정(동적), static 메서드는 변수 선언 타입으로 결정(정적).

**핵심 용어**

- **extends**: 클래스 상속을 선언하는 키워드. Java는 하나의 부모만 상속 가능(단일 상속)
- **super()**: 부모 클래스의 생성자(객체를 만들 때 처음 실행되는 초기화 코드)를 호출. 자식 생성자의 첫 줄에서만 사용 가능
- **super.메서드()**: 부모가 원래 가지고 있던 메서드를 명시적으로 호출할 때 사용
- **@Override**: 오버라이딩 어노테이션(annotation, 코드에 붙이는 보조 정보 표시). 컴파일러가 메서드 시그니처를 검증
- **동적 바인딩(Dynamic Binding)**: 프로그램 실행 시(런타임) 실제 객체 타입으로 호출할 메서드를 결정하는 방식
- **정적 바인딩(Static Binding)**: 코드 해석 시(컴파일 타임) 참조 변수 타입으로 호출할 메서드를 결정하는 방식

## ✅ 스스로 가르쳐보기

이 내용을 처음 듣는 친구에게 설명한다고 생각하고, 본인만의 비유로 **상속과 오버라이딩**을 한 문장으로 정의해보세요.

**체크포인트** — 아래 항목을 스스로 설명할 수 있는지 확인하세요:
- `Animal a = new Dog()`에서 `a.speak()` 호출 시 왜 Dog의 `sound()`가 실행되는지
- static 메서드 호출이 인스턴스 메서드와 다르게 동작하는 이유
- 자식 객체를 만들 때 부모 생성자가 먼저 실행되는 이유
- `@Override`를 빼도 동작은 같은데 왜 붙이는지

## 🎯 시험 응용

> - **2025-1회**: `Animal a = new Dog()` 형태에서 speak() 내부의 sound()가 Dog의 sound()로 동적 바인딩되어 호출됨 — 출력 결과 추적 문제 > - **2025-2회**: static 메서드는 참조 변수 타입 기준으로 바인딩됨 (5P). `A obj = new B()`에서 static 메서드는 A의 것이 호출됨 > - **2024-2회**: 재귀 + 오버라이딩 혼합 문제. 출력 역순(dcba) 추적 필요 > - **출제 패턴**: 코드 주고 출력값 쓰기. 반드시 참조 타입 vs 실제 타입을 구분해야 함
