# Java 상속과 오버라이딩

> 🔥 **매회 출제** (priority 3)

![[pg-language-003.svg]]

## 🌱 왜 배우나

Dog, Cat, Cow, Bird 클래스를 각각 만든다면 "이름, 나이, 자기, 먹기" 같은 공통 속성·동작을 매번 복사해서 붙여야 한다. 중복도 귀찮지만 나중에 공통 부분을 고치려면 모든 클래스를 다 뒤져야 한다. 상속은 "공통된 부모(Animal)를 한 번 만들어 두고, 자식은 부모의 특성을 물려받되 필요한 부분만 덮어쓰자"는 아이디어다. 부모의 설계도를 물려받으면서 자식만의 개성은 새로 정의할 수 있게 하려고 extends와 @Override가 등장했다.

## 📖 핵심 개념

상속(extends)은 부모 클래스의 필드와 메서드를 자식 클래스가 물려받는 메커니즘이다. 오버라이딩(@Override)은 부모의 메서드를 자식이 재정의하는 것으로, 인스턴스 메서드는 **동적 바인딩**에 의해 실제 객체 타입의 메서드가 호출된다. 반면 static 메서드와 필드는 **정적 바인딩**으로 참조 변수의 타입 기준으로 결정된다.

**핵심 용어**

- **extends**: 클래스 상속 선언 키워드. Java는 단일 상속만 허용
- **super()**: 부모 클래스 생성자 호출. 자식 생성자의 첫 줄에서만 사용 가능
- **super.메서드()**: 부모의 오버라이딩된 메서드를 명시적으로 호출
- **@Override**: 오버라이딩 어노테이션. 컴파일러가 시그니처를 검증함
- **동적 바인딩**: 런타임에 실제 객체 타입으로 메서드를 결정 (instance 메서드)
- **정적 바인딩**: 컴파일 타임에 참조 변수 타입으로 결정 (static 메서드, 필드)

## ✅ 이해 확인

1. `@Override` 어노테이션이 하는 일은?
   <details><summary>정답</summary>컴파일러에게 "이 메서드는 부모의 메서드를 재정의한다"고 알려서, 시그니처가 일치하지 않으면 컴파일 에러를 내게 한다. 오타로 인한 재정의 실패를 잡아 준다.</details>
2. `A obj = new B();`일 때 **인스턴스 메서드** 호출은 A/B 중 어느 쪽의 것이 실행되는가?
   <details><summary>정답</summary>B(실제 객체 타입)의 것이 실행된다. 인스턴스 메서드는 런타임에 실제 객체 타입으로 결정되는 **동적 바인딩**을 따르기 때문이다.</details>
3. 위와 같은 상황에서 **static 메서드**를 호출하면 어느 쪽이 실행되는가? 이유는?
   <details><summary>정답</summary>A(참조 변수 타입)의 static 메서드가 실행된다. static 메서드는 객체가 아닌 클래스에 속하므로 컴파일 타임에 참조 타입 기준으로 결정되는 **정적 바인딩**을 따른다. 이를 "오버라이딩"이 아니라 "숨김(hiding)"이라고 부른다.</details>

## 🎯 시험 응용
