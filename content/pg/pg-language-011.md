# Java 예외처리 try-catch-finally

> 🔥 **매회 출제** (priority 3)

![[pg-language-011.svg]]

## 🌱 왜 배우나

프로그램을 실행하다 보면 예상치 못한 사고가 생긴다. 파일을 열려고 했는데 파일이 없거나, 숫자를 0으로 나누거나, 배열의 범위를 벗어나는 식이다. 이런 사고를 예외(exception)라고 부른다. 예외가 터졌을 때 프로그램이 그냥 멈춰버리면 곤란하니까, "사고가 나면 이렇게 대응하라"는 계획을 미리 짜 두는 것이 예외처리(exception handling)다. try 블록(중괄호로 묶은 코드 덩어리)에 정상 코드를 쓰고, catch 블록에 사고 대응 코드를 쓴다. finally 블록은 사고가 났든 안 났든 마지막에 반드시 실행되는 뒷정리 구간이다. 비유하면, try는 요리하는 과정, catch는 불이 나면 소화기를 쓰는 대응, finally는 불이 났든 안 났든 가스 밸브를 잠그는 마무리다.

## 📖 핵심 개념

예외(exception)란 프로그램 실행 중 발생하는 비정상적인 상황을 말한다. Java에서는 try-catch-finally라는 세 구간으로 이를 처리한다. try 블록 안에서 예외가 발생하면, 발생 지점 이후의 try 코드는 전부 건너뛰고 곧바로 catch 블록으로 이동한다. catch는 예외 타입(종류)을 지정하여, 해당 종류의 예외만 잡아서 처리한다. finally 블록은 예외가 발생했든 안 했든 무조건 실행된다. 파일 닫기, 네트워크 연결 해제처럼 반드시 해야 하는 뒷정리를 여기에 쓴다. catch를 여러 개 쓰면 예외 종류별로 다른 대응이 가능하고, 이때 범위가 넓은 상위 타입(Exception)은 맨 마지막에 써야 한다.

## 🔍 시각화

```
┌──────────────────────────────────────────────┐
│              예외 없는 경우                    │
│                                              │
│  try 전체 실행 ──→ finally 실행 ──→ 다음 코드 │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│              예외 발생 시                      │
│                                              │
│  try 일부 실행                                │
│       │                                      │
│       ╳ ← 예외 발생! (이후 try 코드 건너뜀)   │
│       │                                      │
│       ▼                                      │
│  catch 블록 실행 ──→ finally 실행 ──→ 다음    │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│         다중 catch 매칭 순서                   │
│                                              │
│  예외 발생                                    │
│    │                                         │
│    ├─ catch(ArithmeticException)  ← 먼저 비교 │
│    ├─ catch(ArrayIndex...Exception) ← 그 다음 │
│    └─ catch(Exception)           ← 마지막     │
│         (가장 넓은 범위는 맨 아래)             │
└──────────────────────────────────────────────┘
```

## ↔️ 이웃 개념 구분

- **throw vs throws**: `throw`는 코드 안에서 예외를 직접 발생시키는 명령이고, `throws`는 메서드 선언부에 "이 메서드는 이런 예외가 날 수 있다"고 알려주는 표시다.
- **Checked vs Unchecked 예외**: Checked 예외(IOException 등)는 컴파일러가 처리를 강제하고, Unchecked 예외(RuntimeException 등)는 강제하지 않는다.

**핵심 용어**

- **예외(exception)**: 프로그램 실행 중 발생하는 비정상 상황
- **try**: 예외가 발생할 수 있는 코드를 감싸는 블록
- **catch(예외타입 변수)**: 지정한 타입의 예외를 잡아서 처리하는 블록
- **finally**: 예외 발생 여부와 무관하게 반드시 실행되는 블록. 자원 해제(파일 닫기 등) 용도
- **throw**: 예외를 명시적으로 발생시키는 키워드
- **throws**: 메서드 선언부에서 "이 메서드가 발생시킬 수 있는 예외 타입"을 명시
- **RuntimeException**: 실행 시점에 발생하는 예외의 상위 클래스. 컴파일러가 처리를 강제하지 않음(Unchecked)

## ✅ 스스로 가르쳐보기

> 친구에게 "try 블록 중간에 예외가 터지면 프로그램의 실행 흐름이 어떻게 바뀌는지"를 처음부터 끝까지 설명해 보세요. catch와 finally를 각각 왜 쓰는지, 실행 순서는 어떤지까지 말할 수 있어야 합니다.

체크포인트:
- [ ] 예외 발생 지점 이후의 try 코드가 실행되지 않는다는 점을 말했는가
- [ ] catch가 예외 타입별로 다른 대응을 한다는 점을 말했는가
- [ ] finally가 예외 유무와 관계없이 항상 실행된다는 점을 말했는가

## 🎯 시험 응용

> - **2025-1회**: `a/b` (b=0)에서 ArithmeticException 발생 → catch 실행 후 finally 실행. 답: 출력1출력5 > - **출제 패턴**: try 블록 내 예외 발생 지점 이후 코드는 실행되지 않음. catch-finally 순서 추적 > - **핵심**: 예외 발생 시 try의 나머지 코드는 **건너뜀**. finally는 **무조건 실행** > - **주의**: finally에 return이 있으면 try/catch의 return을 덮어씀
