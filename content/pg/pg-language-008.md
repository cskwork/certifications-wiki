# C언어 재귀 함수

> 🔥 **매회 출제** (priority 3)

![[pg-language-008.svg]]

## 🌱 왜 배우나

"1부터 n까지 더하기"는 반복문으로 쓸 수 있지만, 폴더 안에 폴더가 들어 있는 구조를 탐색하거나 팩토리얼(n! = n × (n-1) × … × 1)처럼 자기 자신의 축소판으로 정의되는 문제는 반복문으로 쓰면 코드가 복잡해진다.

재귀는 러시아 인형 마트료시카와 같다. 큰 인형을 열면 똑같이 생긴 작은 인형이 있고, 또 열면 더 작은 인형이 나온다. 마지막에는 더 이상 열 수 없는 가장 작은 인형이 나온다. "나는 한 단계만 처리하고, 나머지는 더 작은 나에게 맡기겠다"는 방식으로 복잡한 반복을 간결하게 표현하기 위해 재귀가 등장했다.

## 📖 핵심 개념

재귀 함수(Recursive Function)는 자기 자신을 호출하는 함수다. 함수 안에서 다시 그 함수를 부르는 것이다. 반드시 종료 조건(Base Case, 더 이상 자기를 부르지 않고 바로 답을 돌려주는 조건)이 있어야 한다. 종료 조건이 없으면 함수가 끝없이 자기를 불러서 스택 오버플로우(호출 기록이 쌓이다가 메모리 공간이 넘치는 오류)가 발생한다. 함수가 호출될 때마다 호출 스택(Call Stack, 함수 호출 기록을 쌓아두는 공간)에 새 기록이 쌓이고, 반환할 때 하나씩 제거된다. 시험에서는 호출 트리(함수가 자기를 어떻게 불렀는지 나뭇가지처럼 그린 그림)를 그려서 반환값을 역추적하는 것이 핵심이다.

## 🔍 시각화

```
팩토리얼 호출 과정: factorial(4)

호출 방향(아래로 내려감)        반환 방향(위로 올라감)

factorial(4)                    → 4 × 6 = 24
  └─ factorial(3)               → 3 × 2 = 6
       └─ factorial(2)          → 2 × 1 = 2
            └─ factorial(1)     → 1  ← 종료 조건(여기서 멈춤)

피보나치 호출 트리: f(5)

              f(5)
           ┌───┴───┐
         f(4)     f(3)
        ┌──┴──┐  ┌──┴──┐
      f(3)  f(2) f(2) f(1)=1
     ┌──┴──┐  │   │
   f(2) f(1) 1   1
    │    =1
    1
→ 같은 값(예: f(2))을 여러 번 중복 계산함
```

## ↔️ 이웃 개념 구분

- **재귀 vs 반복문**: 재귀는 함수가 자기를 다시 부름, 반복문은 같은 코드 블록을 되풀이. 둘 다 같은 결과를 낼 수 있지만 재귀가 더 간결한 경우가 있다.
- **종료 조건(Base Case) vs 재귀 호출(Recursive Case)**: 종료 조건은 "여기서 멈춰", 재귀 호출은 "아직 끝 아니니까 더 작은 문제로 나를 다시 불러".

**핵심 용어**

- **종료 조건(Base Case)**: 재귀 호출을 멈추는 조건. 이것이 없으면 무한 재귀 → 스택 오버플로우(Stack Overflow, 호출 기록이 넘치는 오류)
- **재귀 호출(Recursive Case)**: 자기 자신을 다시 호출하여 문제를 더 작은 단위로 나누는 부분
- **호출 스택(Call Stack)**: 함수 호출마다 기록(스택 프레임)이 하나씩 쌓이고, 함수가 끝나면 하나씩 제거되는 공간
- **꼬리 재귀(Tail Recursion)**: 재귀 호출이 함수의 마지막 연산인 경우. 일부 컴파일러가 최적화(반복문처럼 변환)할 수 있다

**체크포인트** — 아래 항목을 스스로 설명할 수 있는지 확인하세요:
- 종료 조건(Base Case)이 없으면 어떤 일이 벌어지는지
- 재귀 호출이 진행되는 방향과 값이 반환되는 방향이 왜 반대인지
- 피보나치 재귀에서 같은 값을 여러 번 계산하는 문제가 왜 생기는지
- `factorial(4)`의 호출 순서를 직접 따라가며 최종 결과를 구할 수 있는지
