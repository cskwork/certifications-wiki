# 연결 리스트

> 🔥 **매회 출제** (priority 3)

![[pg-data-structure-002.svg]]

## 🌱 왜 배우나

배열은 크기가 고정이라, 중간에 값을 끼워 넣으려면 뒤쪽 원소를 전부 밀어내야 한다. 만 명짜리 명단 맨 앞에 한 명 추가하자고 9,999명을 옮기는 셈이다. 연결 리스트는 "각 데이터에 '다음은 저기로 가세요'라는 보물찾기 쪽지를 붙여두자"는 아이디어다. 데이터가 여기저기 흩어져 있어도 쪽지만 따라가면 순서대로 읽을 수 있고, 끼워 넣을 때는 쪽지 두 장만 고쳐 쓰면 된다. 그래서 삽입·삭제가 잦은 상황을 위해 이 자료구조가 등장했다.

## 📖 핵심 개념

연결 리스트(Linked List)는 노드(데이터 + 포인터)를 동적으로 연결한 자료구조다. 배열과 달리 메모리가 연속적이지 않아 삽입/삭제가 O(1)이지만, 임의 접근은 O(n)이다. 기출에서는 주로 C 구조체 포인터를 이용한 코드를 주고 순회 결과를 추적하는 형식으로 출제된다.

**핵심 용어**

- **노드(Node)**: data 필드 + next 포인터(단일) 또는 prev/next 포인터(이중)
- **head**: 첫 번째 노드를 가리키는 포인터. 리스트의 시작점
- **->**: 포인터로 구조체 멤버 접근 연산자. `p->data` == `(*p).data`
- **단일 연결 리스트**: 한 방향(next)으로만 순회 가능
- **이중 연결 리스트**: prev/next 양방향 순회 가능
- **원형 연결 리스트**: 마지막 노드의 next가 head를 가리킴

## ✅ 이해 확인

1. 단일 연결 리스트에서 `p->next`가 의미하는 것은?
   <details><summary>정답</summary>포인터 p가 가리키는 노드의 next 필드(다음 노드 주소). `(*p).next`와 동일한 표현이다.</details>
2. 배열과 비교할 때 연결 리스트가 **불리한** 연산은?
   <details><summary>정답</summary>임의 접근(i번째 원소 바로 읽기). 배열은 O(1)이지만 연결 리스트는 head부터 순차 탐색해야 해서 O(n)이다.</details>
3. head → [10] → [20] → [30] → NULL 상태에서 값 5를 맨 앞에 삽입하려 한다. 다음 두 줄의 순서를 바꾸면 어떻게 되는가? `newNode->next = head;` / `head = newNode;`
   <details><summary>정답</summary>순서를 뒤집어 `head = newNode;`를 먼저 하면, 그 다음 줄의 `newNode->next = head;`가 자기 자신을 가리키게 되어 [10],[20],[30] 노드를 잃어버린다. 반드시 새 노드의 next부터 연결하고 head를 갱신해야 한다.</details>
