# 보안 공격 유형

> 🔥 **매회 출제** (priority 3)

![[nw-security-001.svg]]

## 🌱 왜 배우나

웹사이트의 로그인 창에 아이디 대신 특수한 명령어를 적어 넣으면 어떻게 될까? 만약 웹사이트가 입력값을 아무런 검사 없이 그대로 처리한다면, 회원 정보가 통째로 유출될 수 있다. 건물에 비유하면, 출입문을 잠그지 않아 아무나 들어와 서류를 뒤지거나, 남의 사원증을 복제해 쓰는 것과 같다. 이런 공격들은 각각 다른 약점(입력값, 세션, 네트워크 등)을 노린다. 방어를 설계하려면 먼저 공격의 종류와 원리를 정확히 알아야 해서 이 분류 체계가 등장했다.

## 📖 핵심 개념

보안 공격이란 시스템의 세 가지 핵심 성질을 위협하는 행위다. 세 가지 핵심 성질이란, 기밀성(허락된 사람만 정보를 볼 수 있음), 무결성(정보가 몰래 바뀌지 않음), 가용성(필요할 때 서비스를 쓸 수 있음)을 말한다. 공격 유형은 크게 네 가지로 나뉜다. 첫째, 서비스 거부 공격(DoS/DDoS) — 서버에 트래픽(데이터 요청)을 폭주시켜 정상 사용을 못 하게 만든다. 둘째, 인젝션(주입) 공격 — 입력란에 악성 코드를 끼워 넣어 서버나 데이터베이스(DB, 데이터 저장소)를 조작한다. 셋째, 세션 탈취 공격 — 이미 로그인한 사용자의 인증 정보를 가로채 대신 행동한다. 넷째, 네트워크 도청(스니핑) — 오가는 데이터를 몰래 엿본다.

## 🔍 시각화

```
  공격 유형 분류

  ┌─────────────────────────────────────────┐
  │            보안 공격                     │
  ├──────────┬──────────┬─────────┬─────────┤
  │ 서비스   │ 인젝션   │ 세션    │ 네트워크│
  │ 거부     │ (주입)   │ 탈취    │ 도청    │
  ├──────────┼──────────┼─────────┼─────────┤
  │ DoS      │ SQL      │ CSRF    │ 스니핑  │
  │ DDoS     │ Injection│         │         │
  │          │ XSS      │         │         │
  ├──────────┼──────────┼─────────┼─────────┤
  │ 가용성↓  │ 기밀성↓  │ 무결성↓ │ 기밀성↓ │
  │          │ 무결성↓  │         │         │
  └──────────┴──────────┴─────────┴─────────┘

  노리는 대상:
  SQL Injection → 서버의 DB
  XSS           → 다른 사용자의 브라우저
  CSRF          → 인증된 사용자의 권한
```

## ↔️ 이웃 개념 구분

- **XSS vs CSRF**: XSS는 악성 스크립트(작은 프로그램)가 "다른 사용자의 브라우저"에서 실행되어 정보를 빼내는 공격. CSRF는 이미 로그인한 사용자가 "자기도 모르게" 공격자가 원하는 요청을 서버에 보내게 만드는 공격. XSS는 스크립트 실행, CSRF는 위조 요청이 핵심이다.
- **DoS vs DDoS**: DoS(Denial of Service, 서비스 거부)는 공격자 1명이 직접 공격. DDoS(Distributed DoS, 분산 서비스 거부)는 수많은 좀비 PC(몰래 감염된 컴퓨터들, 봇넷이라 부름)를 동원해 한꺼번에 공격.

**핵심 용어**

- **DoS/DDoS** (Denial of Service / Distributed DoS, 서비스 거부 / 분산 서비스 거부): 서버에 대량의 요청을 보내 정상 서비스를 마비시키는 공격. DoS는 공격자 1명, DDoS는 다수의 좀비 PC(봇넷, 몰래 감염된 컴퓨터 집단)를 동원. 세부: SYN Flood, Smurf, Land Attack, Ping of Death 등
- **SQL Injection** (SQL 주입): 웹 입력란에 악의적인 SQL(데이터베이스 질의 언어) 구문을 끼워 넣어 DB를 비정상적으로 조작하는 공격. 대응: PreparedStatement(매개변수화 쿼리, 입력값을 코드가 아닌 데이터로 처리), 입력값 검증
- **XSS** (Cross-Site Scripting, 교차 사이트 스크립팅): 웹 페이지에 악성 스크립트를 심어 다른 사용자의 브라우저에서 실행시키는 공격. 쿠키(로그인 정보 조각)·세션(로그인 상태) 탈취 가능. 대응: 입출력 이스케이프(특수문자 무력화) 처리, CSP(Content Security Policy, 콘텐츠 보안 정책) 헤더
- **CSRF** (Cross-Site Request Forgery, 교차 사이트 요청 위조): 로그인 된 사용자가 자신도 모르게 공격자가 만든 요청을 서버에 보내게 만드는 공격. 대응: CSRF 토큰(일회용 인증 코드), Referer(요청 출처) 검증
- **스니핑(Sniffing, 도청)**: 네트워크에서 오가는 데이터(패킷)를 몰래 엿보는 행위. 대응: 암호화 통신(HTTPS, VPN — Virtual Private Network, 가상 사설 네트워크)

## ✅ 스스로 가르쳐보기

"SQL Injection, XSS, CSRF가 각각 '어디를' 노리는 공격인지, 그리고 각각의 대응 방법을 친구에게 설명해 보세요."

체크포인트:
- SQL Injection이 서버의 DB를, XSS가 다른 사용자의 브라우저를, CSRF가 인증된 사용자의 권한을 노린다고 구분할 수 있는가?
- DoS와 DDoS의 차이를 "공격자 수"로 설명할 수 있는가?
- 스니핑의 대응책으로 암호화 통신을 말할 수 있는가?

## 🎯 시험 응용

> 각 공격 유형의 정의를 제시하고 공격 이름을 묻는 문제가 빈출된다. 특히 **SQL Injection**과 **XSS**의 차이(DB 조작 vs 브라우저 스크립트 실행), **DoS**와 **DDoS**의 차이(단일 vs 분산)를 명확히 구분해야 한다. DDoS 세부 공격인 **SYN Flood**(TCP 3-Way Handshake 악용, 대량 SYN 패킷 전송)와 **Smurf Attack**(ICMP 브로드캐스트 악용)도 서술형으로 출제된다.
