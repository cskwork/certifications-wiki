# 모듈 응집도 7단계

> 🔥 **매회 출제** (priority 3)

![[se-cohesion-001.svg]]

## 🌱 왜 배우나

한 모듈 안에 "로그인 처리, 환율 계산, 프린터 출력"이 뒤섞여 있다면 그 모듈은 이름 붙이기조차 애매하고, 수정할 때마다 엉뚱한 기능이 터진다. 이는 마치 한 직원에게 회계·디자인·배송을 모두 맡기는 것과 같아서 어느 것 하나 제대로 돌아가지 않는다. 모듈 내부 구성원은 같은 목적을 위해 협력하는 한 팀이어야 유지보수·재사용·테스트가 쉬워진다. 그래서 "한 모듈 안의 구성 요소들이 얼마나 한 가지 일에 집중되어 있는가"를 측정하는 응집도 개념이 등장했다.

## 📖 핵심 개념

응집도(Cohesion)는 모듈 내부 구성 요소들이 하나의 목적을 위해 얼마나 밀접하게 관련되어 있는가를 나타낸다. 높을수록(강할수록) 좋은 설계이며, 결합도와 반대 방향으로 이해한다. 7단계를 강→약 순서로 암기하고 각 유형의 정의를 구별하는 것이 핵심이다.

**핵심 용어**

- **Functional(기능적) 응집도** [최강]: 모듈 내 모든 요소가 단일 기능 수행에 기여 — 가장 이상적
- **Sequential(순차적) 응집도**: 한 활동의 출력이 다음 활동의 입력으로 연결 — 파이프라인 구조
- **Communication(통신적) 응집도**: 동일한 입력/출력 데이터를 사용하는 활동들의 집합 — 같은 데이터 처리
- **Procedural(절차적) 응집도**: 특정 순서에 따라 수행되어야 하는 활동들의 집합 — 순서 중요, 데이터 무관
- **Temporal(시간적) 응집도**: 특정 시간대에 함께 실행되는 기능들의 집합 — 초기화 루틴, 종료 루틴
- **Logical(논리적) 응집도**: 유사한 성격이나 범주에 속하는 기능들을 하나의 모듈로 묶음 — 제어 플래그로 선택
- **Coincidental(우연적) 응집도** [최약]: 관련 없는 기능들이 우연히 같은 모듈에 존재 — 최악의 설계

## ✅ 이해 확인

1. 응집도 7단계를 강→약 순서로 쓰시오.
   <details><summary>정답</summary>기능적 → 순차적 → 통신적 → 절차적 → 시간적 → 논리적 → 우연적 ("기순통절시논우").</details>
2. "프로그램 시작 시 DB 연결, 로그 초기화, 캐시 로딩을 한 모듈에 모았다"는 어떤 응집도인가?
   <details><summary>정답</summary>시간적(Temporal) 응집도. 같은 시점에 실행되지만 기능적 관련성은 없는 전형적 예시다.</details>
3. Sequential(순차적)과 Procedural(절차적) 응집도의 결정적 차이는 무엇인가?
   <details><summary>정답</summary>데이터 흐름 여부. 순차적은 앞 활동의 "출력이 다음 활동의 입력"으로 이어지는 반면, 절차적은 단순히 "실행 순서"만 정해져 있고 데이터는 서로 독립적이다.</details>

## 🎯 시험 응용

> - **강→약 순서 암기법**: "기순통절시논우" (기능-순차-통신-절차-시간-논리-우연) > - **2024-2회**: 순차적 응집도 정의 빈칸 문제 — "한 활동의 출력이 다음 활동의 입력" > - 순차(Sequential) vs 절차(Procedural) 혼동 주의: 순차는 데이터 흐름, 절차는 실행 순서 > - 응집도는 높을수록 / 결합도는 낮을수록 좋은 설계 — 반드시 함께 암기
