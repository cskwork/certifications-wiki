# GoF 행위 패턴 11가지

> 🔥 **매회 출제** (priority 3)

![[se-design-003.svg]]

## 🌱 왜 배우나

회사에서 부서(팀)들이 잘 나뉘어 있어도, "누가 누구에게 어떻게 일을 전달하는가" 같은 소통 방식이 엉망이면 일이 안 돌아간다. 프로그램도 마찬가지다. 객체(Object, 데이터와 기능의 묶음)들이 아무리 잘 만들어져 있어도, 서로 어떻게 일을 나누고 소통하는지가 정리되지 않으면 코드가 뒤엉킨다. 행위 패턴(Behavioral Pattern)은 "객체들이 어떻게 일을 나누고 소통할 것인가"에 대한 검증된 11가지 방법을 제공한다. 알고리즘(Algorithm, 문제를 푸는 절차) 교체, 이벤트(Event, 사건) 알림, 상태(State, 현재 상황)에 따른 동작 변경 같은 반복 문제를 일관되게 해결할 수 있다.

## 📖 핵심 개념

행위 패턴(Behavioral Pattern)은 객체나 클래스 간의 알고리즘 배분과 책임 분담에 관한 패턴이다. GoF(Gang of Four) 3분류 중 패턴 수가 가장 많다(11가지). 객체끼리 어떻게 소통하는지, 알고리즘을 어떻게 감싸고 교체하는지, 상태 변화를 어떻게 관리하는지를 다룬다. 시험에서 비중이 가장 높은 분류이므로 각 패턴의 이름과 핵심 목적을 정확히 구분해야 한다.

```
  │  Mediator   : 중재자가 객체 간 통신 집중 관리  │
  │  Chain of R.: 요청을 처리자 체인으로 전달     │

  │  Strategy   : 알고리즘을 교체 가능하게 감쌈   │
  │  Template M.: 골격은 고정, 세부만 하위에 위임  │
  │  Interpreter: 문법을 클래스로 표현하여 해석   │
  └──────────────────────────────────────────┘
  ┌─ 상태·행동 관리 ─────────────────────────┐

  │  Command    : 요청을 객체화 → 실행취소 가능   │
  │  Memento    : 상태 스냅샷 저장 → 복원 가능    │
  └──────────────────────────────────────────┘
  ┌─ 순회·연산 분리 ─────────────────────────┐
  │  Iterator   : 내부 구조 모르고 순차 접근     │
  │  Visitor    : 구조와 연산 분리 → 새 연산 추가  │
  └──────────────────────────────────────────┘
```

## ↔️ 이웃 개념 구분

- **Strategy vs State**: Strategy는 외부(사용자)가 알고리즘을 직접 골라서 교체하는 것. State는 객체의 내부 상태가 바뀌면 행동이 자동으로 바뀌는 것. 외부 선택 vs 내부 전이.
- **Facade(구조) vs Mediator(행위)**: 둘 다 통신을 한 곳으로 모으지만, Facade는 단방향(창구가 내부를 감쌈)이고 Mediator는 양방향(중재자가 객체들 사이 소통을 조율)이다. Facade는 구조 패턴이다.

**핵심 용어**

- **Observer(옵저버)**: 한 객체의 상태가 바뀌면, 그 객체를 구독(관찰)하고 있는 다른 객체들에 자동으로 알려주는 패턴. 1:N(일대다) 관계. 이벤트 구독 구조.
- **Strategy(전략)**: 알고리즘(문제 풀이 절차)을 객체로 감싸서, 실행 중에(런타임에) 다른 알고리즘으로 교체할 수 있게 하는 패턴.
- **Command(커맨드)**: 요청(명령)을 객체로 만들어, 실행 취소(Undo)·재실행(Redo)을 지원하는 패턴.
- **Iterator(이터레이터)**: 컬렉션(Collection, 데이터 모음)의 내부 구조를 드러내지 않고 순서대로 하나씩 접근하는 패턴.
- **State(상태)**: 객체의 내부 상태에 따라 행동이 자동으로 바뀌는 패턴. 상태별로 별도 클래스를 만든다.
- **Template Method(템플릿 메서드)**: 알고리즘의 큰 골격(뼈대)을 상위 클래스에 정의하고, 세부 구현은 하위 클래스(서브클래스)에 맡기는 패턴.
- **Visitor(방문자)**: 객체 구조와 연산(처리 로직)을 분리해, 구조를 바꾸지 않고 새로운 연산을 쉽게 추가하는 패턴. 이중 디스패치(Double Dispatch) 기법 사용.
- **Mediator(중재자)**: 객체들이 서로 직접 통신하지 않고, 중재자(조율자) 객체를 통해 소통하게 하는 패턴. 결합도를 줄인다.
- **Memento(메멘토)**: 객체의 현재 상태를 외부에 스냅샷(사진처럼 저장)으로 보관해, 나중에 이전 상태로 되돌릴 수 있게 하는 패턴. Undo(실행 취소) 구현에 사용.
- **Chain of Responsibility(책임 연쇄)**: 요청을 처리할 수 있는 객체들을 체인(사슬)처럼 연결해, 처리할 수 있는 객체를 찾을 때까지 순서대로 전달하는 패턴.
- **Interpreter(인터프리터)**: 언어의 문법 규칙을 클래스로 표현하고, 그 규칙에 따라 문장을 해석하는 패턴.
