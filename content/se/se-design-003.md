# GoF 행위 패턴 11가지

> 🔥 **매회 출제** (priority 3)

![[se-design-003.svg]]

## 🌱 왜 배우나

객체가 잘 설계되어 있어도 "누가 누구에게 무엇을 요청하고, 어떤 알고리즘을 언제 바꾸며, 상태 변화는 어떻게 전달할 것인가" 하는 협력 방식이 엉망이면 시스템은 금방 스파게티가 된다. 이는 회사에서 조직도는 멀쩡한데 부서 간 업무 분담과 보고 체계가 없어서 일이 안 돌아가는 상황과 같다. 행위 패턴은 "객체들이 어떻게 일을 나눠 하고 소통할 것인가"에 대한 검증된 역할 분담 레시피 11가지를 제공한다. 그래서 알고리즘 교체·이벤트 통지·상태 기반 동작 같은 반복 문제를 일관되게 풀 수 있다.

## 📖 핵심 개념

행위 패턴은 객체나 클래스 간의 알고리즘 및 책임 분배에 관한 패턴이다. 객체 간 통신 방식, 알고리즘 캡슐화, 상태 관리 등을 다루며 GoF 3가지 분류 중 패턴 수가 가장 많다(11가지). 시험에서 비중이 가장 높은 분류다.

**핵심 용어**

- **Observer(옵저버)**: 객체 상태 변화 시 의존 객체들에 자동 통지 — "이벤트 구독", 1:N 의존 관계
- **Strategy(전략)**: 알고리즘을 캡슐화하여 교체 가능하게 — "전략 교체", 런타임에 알고리즘 변경
- **Command(커맨드)**: 요청을 객체로 캡슐화하여 실행 취소·재실행 지원 — "명령 객체화"
- **Iterator(이터레이터)**: 컬렉션 내부 구조 노출 없이 순차 접근 — "순회", 내부 표현 독립적 접근
- **State(상태)**: 객체 상태에 따라 행동을 변경 — "상태 기계", 상태별 클래스로 분리
- **Template Method(템플릿 메서드)**: 알고리즘 골격을 상위 클래스에 정의, 세부 구현은 하위 클래스에 위임
- **Visitor(방문자)**: 객체 구조와 연산을 분리하여 새 연산을 쉽게 추가 — "이중 디스패치"
- **Mediator(중재자)**: 객체 간 통신을 중재 객체가 담당 — "통신 집중화", 결합도 감소
- **Memento(메멘토)**: 객체 상태를 외부에 저장하여 이전 상태로 복원 — "스냅샷", Undo 구현
- **Chain of Responsibility(책임 연쇄)**: 요청을 처리할 수 있는 객체를 연쇄적으로 탐색 — "체인"
- **Interpreter(인터프리터)**: 언어의 문법을 클래스로 표현하고 인터프리터 구현

## ✅ 이해 확인

1. 행위 패턴에서 "객체 상태가 변하면 의존 객체들에게 자동으로 통지되는" 1:N 관계 패턴은?
   <details><summary>정답</summary>Observer(옵저버) 패턴. 이벤트 구독 구조의 대표 예시다.</details>
2. "결제 수단(카드/계좌이체/페이)을 런타임에 교체할 수 있도록" 알고리즘을 캡슐화한 패턴은?
   <details><summary>정답</summary>Strategy(전략) 패턴. 알고리즘을 객체로 캡슐화해 교체 가능하게 하는 것이 핵심이다.</details>
3. Strategy와 State 패턴은 구조가 매우 유사한데 어떻게 구분하는가?
   <details><summary>정답</summary>Strategy는 "알고리즘 교체"(클라이언트가 명시적으로 전략을 선택)가 목적이고, State는 "객체의 내부 상태에 따라 자동으로 행동이 바뀌는 것"이 목적이다. 즉 교체 주체가 외부 클라이언트냐, 내부 상태 전이냐가 결정적 차이다.</details>

## 🎯 시험 응용

> - 빈출 Top 3: **Iterator**, **Observer**, **Strategy** — 매회 출제 수준 > - **2024-2회**: Iterator 패턴 설명 빈칸 문제 출제 > - 구조 패턴 Facade와 혼동 주의 — Facade는 구조 패턴, State·Strategy는 행위 패턴 > - "알고리즘 교체" → Strategy, "상태에 따른 행동 변화" → State 구분 필수
