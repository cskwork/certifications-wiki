# UML 다이어그램 종류 (구조/행위 분류)

> 🔥 **매회 출제** (priority 3)

![[se-requirements-001.svg]]

## 🌱 왜 배우나

집을 짓기 전에 설계도가 필요하듯, 프로그램을 만들기 전에도 "이 시스템이 어떤 부품으로 이루어져 있고, 어떻게 동작하는가"를 그림으로 표현해야 한다. 그런데 개발자·기획자·고객이 각자 다른 방식으로 그림을 그리면 소통이 안 된다. UML(Unified Modeling Language, 통합 모델링 언어)은 "시스템을 누구나 같은 방식으로 그리자"는 국제 표준 시각 언어다. UML 다이어그램(Diagram, 도표)은 크게 두 종류로 나뉜다. 멈춰 있는 구조(뭐가 있는가)를 보여주는 것과, 움직이는 행위(어떻게 동작하는가)를 보여주는 것이다. 어떤 다이어그램이 어느 분류에 속하는지 구분하는 것이 시험의 기본이다.

## 📖 핵심 개념

UML(Unified Modeling Language, 통합 모델링 언어)은 소프트웨어 시스템을 시각적으로 표현하는 표준 언어다. UML 다이어그램은 크게 구조 다이어그램(Structural Diagram, 정적인 구조를 표현)과 행위 다이어그램(Behavioral Diagram, 동적인 동작을 표현)으로 나뉜다. 구조 다이어그램은 "시스템에 무엇이 있는가"를 보여주고, 행위 다이어그램은 "시스템이 어떻게 동작하는가"를 보여준다. 구조 쪽에 7종, 행위 쪽에 7종이 있으며, 행위 다이어그램의 하위 분류로 상호작용 다이어그램(Interaction Diagram)이 있다.

## 🔍 시각화

```
  UML 다이어그램 분류 (UML 2.5 기준)

  ┌─────────────────────────────────────────────┐
  │              UML 다이어그램                   │
  ├───────────────────┬─────────────────────────┤
  │  구조 (7종)       │  행위 (7종)              │
  │  "무엇이 있는가"  │  "어떻게 동작하는가"     │
  ├───────────────────┼─────────────────────────┤
  │  · 클래스         │  · 유스케이스            │
  │  · 객체           │  · 활동                  │
  │  · 컴포넌트       │  · 상태                  │
  │  · 배치           │  ┌ 상호작용 다이어그램 ┐ │
  │  · 복합구조       │  │ · 시퀀스            │ │
  │  · 패키지         │  │ · 커뮤니케이션      │ │
  │  · 프로파일       │  │ · 상호작용 개요     │ │
  │                   │  │ · 타이밍            │ │
  │                   │  └────────────────────┘ │
  └───────────────────┴─────────────────────────┘

  ※ "배치"는 하드웨어 배치(정적)이므로 구조 다이어그램!
```

## ↔️ 이웃 개념 구분

- **구조 vs 행위 다이어그램**: 구조는 "시스템에 무엇이 있는가"(정적), 행위는 "시스템이 어떻게 동작하는가"(동적). "배치(Deployment) 다이어그램"은 이름 때문에 행위로 혼동하기 쉬우나, 하드웨어 노드의 배치라는 정적 정보이므로 구조 다이어그램이다.
- **상호작용 다이어그램**: 행위 다이어그램의 하위 분류. 시퀀스·커뮤니케이션·상호작용 개요·타이밍 4종이 여기에 속한다. 행위 다이어그램이면서 동시에 상호작용 다이어그램인 것이다.

**핵심 용어**

- **구조 다이어그램(Structural Diagram, 정적 구조를 표현하는 도표)** — 7종: 클래스, 객체, 컴포넌트(Component, 독립 배포 가능한 부품), 배치(Deployment, 하드웨어 노드 배치), 복합구조, 패키지(Package, 관련 요소 묶음), 프로파일. 일부 수험서는 프로파일 제외 6종으로 기술한다.
- **행위 다이어그램(Behavioral Diagram, 동적 동작을 표현하는 도표)** — 7종: 유스케이스(Use Case, 사용자와 시스템 간 상호작용), 시퀀스(Sequence, 시간 순서에 따른 메시지 흐름), 커뮤니케이션(Communication, 객체 간 메시지 교환), 상태(State, 상태 변화), 활동(Activity, 작업 흐름), 상호작용 개요(Interaction Overview), 타이밍(Timing).
- **상호작용 다이어그램(Interaction Diagram)**: 행위 다이어그램의 하위 분류로 시퀀스·커뮤니케이션·상호작용 개요·타이밍 4종이 포함된다.
- **유스케이스 다이어그램(Use Case Diagram)**: 사용자(액터, Actor)와 시스템 간의 상호작용을 표현하는 행위 다이어그램. 요구사항 분석 단계에서 가장 많이 쓴다.

## ✅ 스스로 가르쳐보기

> 친구에게 "UML 다이어그램의 두 가지 분류"를 처음부터 설명한다고 생각하고, 각 분류에 어떤 다이어그램들이 속하는지 말로 풀어보라.

체크포인트:
- [ ] 구조와 행위 두 분류를 "정적/동적"으로 구분해 설명했는가?
- [ ] 배치 다이어그램이 구조에 속하는 이유를 설명했는가?
- [ ] 상호작용 다이어그램 4종(시퀀스, 커뮤니케이션, 상호작용 개요, 타이밍)을 언급했는가?
- [ ] 유스케이스 다이어그램이 행위 분류에 속한다는 점을 언급했는가?

## 🎯 시험 응용

> 시퀀스, 커뮤니케이션, 활동, 상태, 유스케이스는 행위 다이어그램이다. 클래스, 객체, 컴포넌트, 배치는 구조 다이어그램이다. 특히 "배치 다이어그램"을 행위로 혼동하는 경우가 많으므로 주의할 것. 암기법: **구조 = 정적(무엇이 있는가)**, **행위 = 동적(어떻게 동작하는가)**.
