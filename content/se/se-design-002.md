# GoF 구조 패턴 7가지

> 🔥 **매회 출제** (priority 3)

![[se-design-002.svg]]

## 🌱 왜 배우나

레고 블록을 조립할 때를 떠올려보자. 블록 모양이 안 맞으면 변환 블록을 끼우고, 블록 위에 장식을 덧붙이고, 복잡한 내부를 커버로 가리기도 한다. 프로그램에서도 이미 만들어진 객체(Object, 데이터와 기능의 묶음)들을 조합해 더 큰 구조를 만들 때 같은 문제가 생긴다. 인터페이스(Interface, 서로 대화하는 규격)가 안 맞거나, 기능을 덧붙이고 싶거나, 복잡한 내부를 숨기고 싶을 때다. 구조 패턴(Structural Pattern)은 "이미 있는 객체들을 어떻게 조립할 것인가"에 대한 검증된 7가지 방법을 제공한다.

## 📖 핵심 개념

구조 패턴(Structural Pattern)은 클래스나 객체를 조합해 더 큰 구조를 만드는 패턴이다. GoF(Gang of Four, 디자인 패턴을 정리한 4명의 저자) 패턴 3분류 중 하나로, 인터페이스 호환(규격 맞추기), 기능 확장(기능 덧붙이기), 접근 제어(접근 막기), 복잡성 은닉(복잡한 내부 숨기기) 같은 목적으로 쓴다. 7가지 패턴 각각의 목적과 구조 차이를 구분하는 것이 시험의 핵심이다.

## 🔍 시각화

```
  GoF 구조 패턴 7가지 — 핵심 목적 한눈에 보기

  ┌────────────┬──────────────────────────────┐
  │ Adapter    │ 규격이 안 맞는 것을 변환     │
  ├────────────┼──────────────────────────────┤
  │ Bridge     │ 추상(기능)과 구현을 분리     │
  ├────────────┼──────────────────────────────┤
  │ Composite  │ 개별과 전체를 동일 취급      │
  ├────────────┼──────────────────────────────┤
  │ Decorator  │ 기능을 동적으로 덧붙임       │
  ├────────────┼──────────────────────────────┤
  │ Facade     │ 복잡한 내부에 단순 창구 제공 │
  ├────────────┼──────────────────────────────┤
  │ Flyweight  │ 공유로 메모리 절약           │
  ├────────────┼──────────────────────────────┤
  │ Proxy      │ 대리인이 접근 제어           │
  └────────────┴──────────────────────────────┘

  Decorator vs Adapter 비교:

  [원본 객체] ─감싸기─▶ [Decorator]  → 기능 추가 (인터페이스 동일)
  [원본 객체] ─감싸기─▶ [Adapter]    → 규격 변환 (인터페이스 변경)
```

## ↔️ 이웃 개념 구분

- **Decorator vs Adapter**: 둘 다 기존 객체를 감싸지만, Decorator는 인터페이스를 그대로 두고 기능을 추가하고, Adapter는 인터페이스 자체를 다른 형태로 변환한다. 기능 확장 vs 규격 변환.
- **Facade vs Proxy**: Facade는 복잡한 여러 객체를 하나의 단순 창구로 묶는 것이고, Proxy는 하나의 특정 객체에 대한 접근을 대리인이 제어하는 것.

**핵심 용어**

- **Adapter(어댑터)**: 호환되지 않는 인터페이스(규격)를 연결하는 변환기. 기존 클래스(이미 만들어진 코드)를 수정하지 않고 새 시스템에서 재사용할 수 있게 한다.
- **Proxy(프록시)**: 실제 객체 대신 대리 객체(대리인)를 두어 접근을 제어한다. 보안 검사, 캐싱(자주 쓰는 데이터 임시 저장), 지연 로딩(필요할 때 비로소 불러오기)에 활용한다.
- **Bridge(브리지)**: 추상화(기능 정의)와 구현(실제 동작)을 분리해 각각 독립적으로 확장할 수 있게 한다.
- **Decorator(데코레이터)**: 객체에 동적으로(실행 중에) 새로운 기능을 덧붙인다. 상속(Inheritance, 부모 클래스의 기능을 물려받는 것) 없이 기능을 확장하는 방법이다.
- **Facade(파사드)**: 복잡한 서브시스템(여러 객체로 이루어진 내부)에 단순한 창구(인터페이스)를 하나 제공한다. 은행 창구처럼 내부 복잡성을 가린다.
- **Composite(컴포지트)**: 개별 객체와 복합 객체(여러 객체의 묶음)를 동일하게 취급한다. 파일/폴더 같은 트리(나무 가지) 구조를 구현할 때 쓴다.
- **Flyweight(플라이웨이트)**: 여러 객체가 공통 데이터를 공유해 메모리를 절약한다. 공유 가능한 상태(intrinsic, 변하지 않는 부분)를 분리하는 것이 핵심이다.

## 🎯 시험 응용

> - **2025-1회**: Adapter 패턴 — 기존 클래스의 인터페이스를 클라이언트가 원하는 형태로 변환하는 패턴 > - **2025-2회**: Proxy 패턴 — 다른 객체에 대한 접근을 제어하기 위한 대리자를 제공하는 패턴 > - **2024-2회**: Iterator 패턴 출제 — **Iterator는 행위 패턴**이므로 구조 패턴과 혼동하지 말 것. 구조 패턴 중 가장 빈출은 Adapter와 Proxy > - 패턴명 영문 표기 + 한글 목적 한 줄 요약을 함께 암기할 것
