# GoF 구조 패턴 7가지

> 🔥 **매회 출제** (priority 3)

![[se-design-002.svg]]

## 🌱 왜 배우나

기존 라이브러리를 새 시스템에 붙이려는데 인터페이스가 안 맞거나, 복잡한 내부 구조를 외부에 노출하고 싶지 않거나, 객체에 기능을 덕지덕지 추가하고 싶을 때가 있다. 매번 임시 코드로 처리하면 레고 블록마다 모양이 제각각이어서 조립이 불가능해진다. 구조 패턴은 "이미 있는 객체들을 어떻게 조립해 더 큰 구조를 만들 것인가"에 대한 검증된 레시피 7가지를 제공한다. 그래서 호환·확장·은닉 같은 반복 문제를 일관된 방법으로 해결할 수 있다.

## 📖 핵심 개념

구조 패턴은 클래스나 객체를 조합하여 더 큰 구조를 만드는 패턴이다. 인터페이스 호환, 기능 확장, 접근 제어, 복잡성 은닉 등의 목적으로 사용된다. 7가지 패턴 각각의 목적과 구조의 차이를 명확히 구분하는 것이 시험의 핵심이다.

**핵심 용어**

- **Adapter(어댑터)**: 호환되지 않는 인터페이스를 연결 — "변환기", 기존 클래스를 수정 없이 재사용
- **Proxy(프록시)**: 실제 객체 대신 대리 객체를 통해 접근 제어 — "대리인", 보안·캐싱·지연 로딩에 활용
- **Bridge(브리지)**: 추상화와 구현을 분리하여 독립적으로 확장 — "분리", 구현부와 기능부를 별도 계층으로
- **Decorator(데코레이터)**: 객체에 동적으로 새로운 기능 추가 — "포장지", 상속 없이 기능 확장
- **Facade(파사드)**: 복잡한 서브시스템에 단순한 인터페이스 제공 — "창구", 서브시스템 의존성 감소
- **Composite(컴포지트)**: 개별 객체와 복합 객체를 동일하게 취급 — "트리구조", 파일/폴더 계층 구현
- **Flyweight(플라이웨이트)**: 공유를 통해 다수의 유사 객체를 효율적으로 지원 — "메모리 절약", 공유 상태(intrinsic) 분리

## ✅ 이해 확인

1. GoF 구조 패턴 7가지를 모두 쓰시오.
   <details><summary>정답</summary>Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy (어브컴데파플프).</details>
2. "실제 이미지 객체 대신 대리 객체를 두어 로딩을 지연시키고 접근을 제어하는" 패턴은?
   <details><summary>정답</summary>Proxy(프록시) 패턴. 보안·캐싱·지연 로딩이 대표적 활용 예이다.</details>
3. Decorator 패턴과 Adapter 패턴은 둘 다 기존 객체를 감싸는데 어떻게 다른가?
   <details><summary>정답</summary>Adapter는 "호환되지 않는 인터페이스를 원하는 형태로 변환"하는 것이 목적이고, Decorator는 "기존 인터페이스는 그대로 두고 동적으로 새 기능을 추가"하는 것이 목적이다. 변환 vs 기능 확장이 결정적 차이다.</details>

## 🎯 시험 응용

> - **2025-1회**: Adapter 패턴 — 기존 클래스의 인터페이스를 클라이언트가 원하는 형태로 변환하는 패턴 > - **2025-2회**: Proxy 패턴 — 다른 객체에 대한 접근을 제어하기 위한 대리자를 제공하는 패턴 > - **2024-2회**: Iterator 패턴 출제 — **Iterator는 행위 패턴**이므로 구조 패턴과 혼동하지 말 것. 구조 패턴 중 가장 빈출은 Adapter와 Proxy > - 패턴명 영문 표기 + 한글 목적 한 줄 요약을 함께 암기할 것
