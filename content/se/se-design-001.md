# 디자인패턴 - GoF 생성패턴 5가지

> 🔥 **매회 출제** (priority 3)

![[se-design-001.svg]]

## 🌱 왜 배우나

빵을 만들 때마다 밀가루·물·이스트를 매번 직접 계량하고 섞는다고 생각해보자. 레시피가 바뀌면 빵 만드는 곳을 전부 찾아다니며 고쳐야 한다. 프로그램에서 객체(Object, 프로그램 안에서 데이터와 기능을 묶어 놓은 덩어리)를 만드는 것도 마찬가지다. 객체를 만들 때마다 구체적인 만드는 방법을 코드 곳곳에 직접 적어 놓으면, 방법이 바뀔 때 모든 곳을 고쳐야 한다. 생성 패턴(Creational Pattern)은 "객체를 어떻게 만들 것인가"라는 반복 문제를 검증된 방법으로 해결한다. 만드는 방법을 한 곳에 모아두니, 나중에 바꿀 때 그 한 곳만 고치면 된다.

## 📖 핵심 개념

디자인 패턴(Design Pattern)이란 프로그래밍에서 자주 반복되는 문제를 해결하는 검증된 설계 방법이다. GoF(Gang of Four, 디자인 패턴을 정리한 4명의 저자)가 정리한 23가지 패턴은 생성(Creational, 객체 만들기) 5개, 구조(Structural, 객체 조립하기) 7개, 행위(Behavioral, 객체 간 소통하기) 11개로 분류된다. 생성 패턴은 객체를 만드는 방법을 사용 코드(실제 기능을 수행하는 코드)로부터 분리해서, 어떤 구체 클래스(실제 구현체)를 쓰는지 감추고 유연성을 높인다. 5가지 이름과 각각의 핵심 목적을 구분하는 것이 시험의 포인트다.

## 🔍 시각화

```
  GoF 디자인패턴 분류 (23개)
  ┌─────────────────────────────────────────┐
  │  생성 (5개)  │  구조 (7개)  │  행위 (11개) │
  └─────────────────────────────────────────┘

  생성패턴 5가지와 핵심 키워드:

  ┌──────────────────┐
  │ Abstract Factory │──▶ 관련 객체 "군(family)" 통째로 생성
  ├──────────────────┤
  │ Builder          │──▶ 복잡한 객체를 "단계별로" 조립
  ├──────────────────┤
  │ Factory Method   │──▶ 생성을 "하위 클래스에 위임"
  ├──────────────────┤
  │ Prototype        │──▶ 기존 객체를 "복제(clone)"
  ├──────────────────┤
  │ Singleton        │──▶ 인스턴스 "딱 하나만" 보장
  └──────────────────┘
```

## ↔️ 이웃 개념 구분

- **Abstract Factory vs Factory Method**: Abstract Factory는 서로 관련된 객체 묶음(군, family)을 통째로 만드는 것. Factory Method는 객체 하나의 생성을 하위 클래스에 맡기는 것. 제품군 vs 단일 제품이 핵심 차이.
- **Builder vs Prototype**: Builder는 복잡한 객체를 단계별로 새로 조립하는 것. Prototype은 이미 있는 객체를 복사해서 새 객체를 만드는 것. 조립 vs 복제가 핵심 차이.

**핵심 용어**

- **Abstract Factory(추상 팩토리)**: 서로 관련된 객체군(family, 한 세트로 묶이는 객체들)을 만드는 틀(인터페이스, Interface)을 제공한다. 구체 팩토리(실제 만드는 곳)를 바꾸면 제품군 전체가 바뀐다.
- **Builder(빌더)**: 복잡한 객체의 만드는 과정(생성 절차)과 최종 모습(표현)을 분리한다. 같은 절차로 다른 결과물을 만들 수 있다.
- **Factory Method(팩토리 메서드)**: 객체 만들기를 하위 클래스(서브클래스, Subclass)에 위임한다. 상위 클래스는 "뭘 만들지"의 틀만 정의하고, 하위 클래스가 실제 만들 대상을 결정한다.
- **Prototype(프로토타입)**: 기존 객체를 복제(clone, 똑같이 베끼기)해서 새 객체를 만든다. 객체를 처음부터 만드는 비용이 클 때 유용하다.
- **Singleton(싱글턴)**: 클래스의 인스턴스(Instance, 실제로 만들어진 객체)를 딱 하나만 만들고, 어디서든 그 하나에 접근할 수 있게 한다.

## 🎯 시험 응용

> 암기법: **"AB를 FPS로 만든다"** (Abstract Factory, Builder, Factory Method, Prototype, Singleton). 생성패턴은 총 5개, 구조패턴 7개(어댑터, 브리지, 컴포지트, 데코레이터, 퍼사드, 플라이웨이트, 프록시), 행위패턴 11개이다. 패턴 이름과 분류를 정확히 매칭하는 문제가 자주 출제된다.
