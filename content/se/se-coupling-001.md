# 모듈 결합도 6단계

> 🔥 **매회 출제** (priority 3)

![[se-coupling-001.svg]]

## 🌱 왜 배우나

레고 블록을 조립할 때, 블록끼리 끼웠다 빼기가 쉬우면 원하는 모양을 자유롭게 만들 수 있다. 그런데 블록끼리 접착제로 붙여버리면? 하나를 떼려다 옆 블록까지 부서진다. 프로그램의 모듈(module, 하나의 기능 덩어리)도 마찬가지다. 모듈끼리 너무 강하게 엮여 있으면 한 모듈을 고칠 때 다른 모듈이 줄줄이 깨진다. 이 "모듈끼리 얼마나 엮여 있는가"를 측정하는 척도가 결합도(Coupling, 모듈 간 상호 의존 정도)다. 결합도가 낮을수록(약할수록) 모듈을 독립적으로 수정·테스트·재사용할 수 있어 좋은 설계가 된다.

## 📖 핵심 개념

결합도(Coupling)란 모듈 사이의 상호 의존 정도를 나타내는 척도다. 낮을수록(약할수록) 좋은 설계이며, 응집도(Cohesion, 모듈 내부 요소들의 관련도 — se-cohesion-001 참고)와 반대 방향이다. 6단계가 있으며 강→약 순서대로 내용·공통·외부·제어·스탬프·자료다. 가장 강한 내용 결합도는 다른 모듈의 내부를 직접 건드리는 최악의 상태이고, 가장 약한 자료 결합도는 단순한 값만 주고받는 이상적 상태다. 시험에서는 각 단계의 정의를 키워드로 정확히 구분하는 것이 핵심이다.

## 🔍 시각화

```
  결합도 강도 스펙트럼 (나쁨 ← → 좋음)

  강(나쁨)                              약(좋음)
   ┃                                     ┃
   ▼                                     ▼
  ┌────┬────┬────┬────┬──────┬────┐
  │내용│공통│외부│제어│스탬프│자료│
  └────┴────┴────┴────┴──────┴────┘
    ▲                              ▲
    │                              │
  내부 코드를                   단순 값만
  직접 참조                     주고받음

  각 단계 핵심 키워드:

  내용 ── 다른 모듈 내부를 직접 참조/수정
  공통 ── 전역 변수(모두가 보는 변수) 공유
  외부 ── 외부 데이터 형식/규약 공유
  제어 ── 제어 플래그(스위치 값) 전달
  스탬프 ── 구조체(묶음 데이터) 전달, 일부만 사용
  자료 ── 단순 값(숫자, 문자 등)만 전달
```

## ↔️ 이웃 개념 구분

- **결합도 vs 응집도**: 결합도는 모듈 "사이"의 의존도(낮을수록 좋음). 응집도는 모듈 "내부" 요소들의 관련도(높을수록 좋음). 항상 세트로 출제된다.
- **공통(Common) vs 외부(External)**: 둘 다 데이터를 공유하지만, 공통은 프로그램 안의 전역 변수를, 외부는 프로그램 바깥의 데이터 형식·통신 규약을 공유한다.

**핵심 용어**

- **Content(내용) 결합도** [최강]: 다른 모듈의 내부 데이터나 코드를 직접 참조하거나 수정하는 것. 모듈 독립성을 완전히 파괴하는 최악의 결합.
- **Common(공통) 결합도**: 두 모듈이 전역 변수(Global Variable, 프로그램 어디서든 접근 가능한 변수)를 함께 사용하는 것.
- **External(외부) 결합도**: 외부에서 정해진 데이터 형식이나 통신 규약(프로토콜, Protocol)을 함께 따르는 것. 공통 결합도와 비슷하나 공유 대상이 프로그램 바깥 환경이다.
- **Control(제어) 결합도**: 한 모듈이 다른 모듈에 제어 플래그(flag, "이렇게 동작하라"는 스위치 값)를 넘겨 실행 경로를 결정하는 것.
- **Stamp(스탬프) 결합도**: 모듈 사이에 구조체(레코드·배열 같은 묶음 데이터)를 통째로 넘기되, 받는 쪽이 그중 일부만 사용하는 것.
- **Data(자료) 결합도** [최약]: 모듈 사이에 단순한 값(숫자, 문자열 같은 스칼라 값)만 주고받는 것. 가장 이상적인 결합.
