# CPU 스케줄링 알고리즘 (FCFS, SJF, SRT, RR, 우선순위)

> 🔥 **매회 출제** (priority 3)

![[mt-scheduling-001.svg]]

## 🌱 왜 배우나

CPU는 한 번에 하나의 프로세스만 실행할 수 있는데, 수십~수백 개의 프로세스가 동시에 CPU를 요구한다. 정책 없이 순서를 정하면 긴 작업 뒤에 선 짧은 작업이 하염없이 기다려 시스템이 체감상 "먹통"이 된다. 마치 은행 창구에서 먼저 온 고객만 받느냐, 간단한 업무 고객을 먼저 처리하느냐, 번호표를 시간 단위로 돌려가며 받느냐에 따라 평균 대기시간이 완전히 달라지는 것과 같다. 그래서 FCFS, SJF, SRT, RR, 우선순위 같은 CPU 스케줄링 알고리즘이 등장했다.

## 📖 핵심 개념

CPU 스케줄링은 준비 큐에 있는 프로세스 중 어떤 프로세스에 CPU를 할당할지 결정하는 알고리즘이다. **선점(Preemptive)** 방식은 실행 중인 프로세스를 강제로 중단시킬 수 있고, **비선점(Non-preemptive)** 방식은 프로세스가 자발적으로 CPU를 반납할 때까지 기다린다. 평균 대기시간과 평균 반환시간 계산이 핵심 출제 포인트이다.

**핵심 용어**

- **도착시간(Arrival Time)**: 프로세스가 준비 큐에 도착한 시간
- **버스트 시간(Burst Time)**: CPU를 사용하는 시간
- **완료시간(Completion Time)**: 프로세스 실행 완료 시간
- **반환시간(Turnaround Time)** = 완료시간 - 도착시간
- **대기시간(Waiting Time)** = 반환시간 - 버스트시간

## ✅ 이해 확인

1. **비선점(Non-preemptive)** 방식과 **선점(Preemptive)** 방식의 차이는 무엇인가?
   <details><summary>정답</summary>비선점은 실행 중인 프로세스가 스스로 CPU를 반납할 때까지 기다리고, 선점은 더 우선순위가 높거나 짧은 작업이 오면 실행 중인 프로세스를 강제로 중단시킨다.</details>
2. P1(버스트:6), P2(버스트:4), P3(버스트:2)가 동시에 도착했을 때 **SJF**로 처리하면 평균 대기시간은?
   <details><summary>정답</summary>2.67ms — 짧은 순(P3→P2→P1)으로 실행하여 대기시간은 0, 2, 6이고 평균은 (0+2+6)/3 = 2.67ms.</details>
3. **SJF**의 기아(Starvation) 문제를 해결하는 기법과, **RR**에서 타임퀀텀이 너무 작을 때 생기는 부작용은?
   <details><summary>정답</summary>SJF 기아는 **에이징(Aging)**(대기 시간이 길어질수록 우선순위를 점진적으로 올림)으로 해결. RR은 타임퀀텀이 너무 작으면 **문맥 교환(Context Switch) 오버헤드**가 커져 CPU가 실제 작업보다 교체에 시간을 더 쓴다.</details>

## 🎯 시험 응용

> **2025-2회**: SJF/SRT 비교 + 라운드 로빈 타임퀀텀=3일 때 평균 반환시간 11.75ms 계산 문제 출제. > **2025-2회**: 라운드 로빈에서 타임퀀텀이 클수록 FCFS에 가까워지고, 작을수록 문맥교환 오버헤드 증가. > **2024-2회**: SRT 평균 대기시간 6.5ms 계산 문제 — 각 타임슬롯마다 남은 버스트시간 재계산 필수. > 계산 문제는 **간트 차트(Gantt Chart)**를 직접 그리며 타임라인을 시각화하면 오류 방지.
