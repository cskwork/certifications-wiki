# 소프트웨어 테스트 기법 — 화이트박스 vs 블랙박스

> 🔥 **매회 출제** (priority 3)

![[mt-testing-001.svg]]

## 🌱 왜 배우나

자동차를 점검한다고 생각해 보자. 보닛을 열어 엔진 내부를 뜯어보는 점검이 있고, 그냥 시동을 걸고 운전해 보면서 이상한 점을 찾는 점검이 있다. 소프트웨어 결함도 마찬가지로 두 종류가 있다. 코드 내부를 들여다봐야만 발견할 수 있는 것(특정 조건에서만 실행되지 않는 코드 등)과, 겉에서 기능을 써 봐야 드러나는 것(입력값 범위 처리 오류 등)이다. 한쪽만으로는 결함을 놓치기 때문에, 내부 구조를 보는 화이트박스 테스트와 외부 동작만 보는 블랙박스 테스트 두 가지 접근법이 등장했다.

## 📖 핵심 개념

소프트웨어 테스트는 "어디를 보고 테스트하느냐"에 따라 두 축으로 나뉜다. 화이트박스(White-box) 테스트는 프로그램의 소스 코드(내부 로직)를 보면서 "코드의 모든 줄, 모든 분기가 실행되었는가?"를 확인한다. 블랙박스(Black-box) 테스트는 코드를 보지 않고, 기능 명세서(프로그램이 해야 할 일을 적은 문서)만 보면서 "입력에 대해 올바른 출력이 나오는가?"를 확인한다. 화이트박스는 커버리지(Coverage, 코드가 실행된 비율)를 높이는 데, 블랙박스는 요구사항 대비 기능의 정확성을 검증하는 데 초점을 맞춘다.

```
  ├────────────────────┼─────────────────────┤

  │ · 조건 커버리지     │ · 원인-결과 그래프   │

  │ · 경로 커버리지     │ · 상태 전이 테스트   │

```

## ↔️ 이웃 개념 구분

- **검증(Verification) vs 확인(Validation)**: 검증은 "제품을 올바르게 만들고 있는가?"(개발 과정 중 점검), 확인은 "올바른 제품을 만들었는가?"(최종 결과가 사용자 요구를 충족하는지 점검). 둘 다 "V"로 시작하지만 대상이 다르다.
- **분기 커버리지 vs 조건 커버리지**: 분기 커버리지는 if문 전체의 참/거짓 결과를 모두 실행하는 것. 조건 커버리지는 if문 안의 개별 조건 하나하나가 참/거짓을 모두 갖도록 실행하는 것. 조건 커버리지를 만족해도 분기 커버리지를 반드시 만족하는 것은 아니다.

**핵심 용어**

- **화이트박스 테스트 (구조적 테스트, White-box Test)**: 소스 코드의 내부 로직을 보고 테스트하는 방법. 세부 기법: 구문 커버리지(Statement Coverage — 모든 코드 줄 실행), 결정 커버리지(Decision Coverage = 분기 커버리지, Branch Coverage — 모든 분기의 참/거짓 실행), 조건 커버리지(Condition Coverage — 개별 조건식 각각의 참/거짓 실행), 경로 커버리지(Path Coverage — 모든 가능한 실행 경로 실행), MC/DC(Modified Condition/Decision Coverage — 각 조건이 독립적으로 결과에 영향을 주는지 확인)
- **블랙박스 테스트 (기능적 테스트, Black-box Test)**: 코드를 보지 않고 기능 명세만으로 테스트하는 방법. 세부 기법: 동치 분할(Equivalence Partitioning — 입력값을 유효/무효 그룹으로 나누어 대표값 테스트), 경계값 분석(Boundary Value Analysis — 그룹 경계 부근의 값으로 테스트), 원인-결과 그래프, 의사결정 테이블, 상태 전이 테스트, 유스케이스 테스트
- **커버리지 강도 순서**: 구문 < 결정(분기) < 조건 < 조건/결정 < MC/DC < 경로. 경로 커버리지가 가장 강력하지만 경우의 수가 폭발적으로 늘어 현실적으로 불가능한 경우가 많다. 주의: 조건 커버리지가 분기 커버리지를 반드시 포함하지는 않는다
- **경험 기반 테스트**: 오류 추정(Error Guessing — 자주 틀리는 부분을 경험으로 짐작해 테스트), 탐색적 테스트(Exploratory Testing — 테스트 계획 없이 실시간으로 프로그램을 탐색하며 테스트)
- **검증(Verification)**: "올바르게 만들고 있는가?" — 개발 과정에서 설계·명세 대비 점검
- **확인(Validation)**: "올바른 것을 만들었는가?" — 최종 제품이 사용자 요구를 충족하는지 점검

## ✅ 스스로 가르쳐보기

"화이트박스 테스트와 블랙박스 테스트의 차이를 '무엇을 보고 테스트하느냐'로 설명하고, 각각의 대표 기법을 2개씩 친구에게 말해 보세요."

체크포인트:
- 동치 분할과 경계값 분석이 블랙박스 기법인 이유를 설명할 수 있는가?
- 커버리지 강도 순서(구문 < 분기 < 조건 < MC/DC < 경로)를 나열할 수 있는가?
- 검증(Verification)과 확인(Validation)이 각각 어떤 질문에 답하는지 한 줄로 말할 수 있는가?

## 🎯 시험 응용

> **화이트박스 기법과 블랙박스 기법의 분류** 문제가 매우 빈출된다. 동치 분할, 경계값 분석은 블랙박스, 구문/결정/조건/경로 커버리지는 화이트박스임을 반드시 구분해야 한다. **커버리지 강도 순서**와 각 커버리지의 정의를 서술하는 문제도 출제된다. 검증(Verification)과 확인(Validation)의 차이도 빈칸 채우기로 자주 나온다.
