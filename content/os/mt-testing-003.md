# 테스트 커버리지 (문장, 분기, 조건, MC/DC, 경로)

> 🔥 **매회 출제** (priority 3)

![[mt-testing-003.svg]]

## 🌱 왜 배우나

"테스트를 많이 돌렸다"는 말만으로는 품질을 보장할 수 없다. 100개의 테스트가 실제로는 같은 코드 몇 줄만 반복 실행했다면, 나머지 분기와 경로는 한 번도 검증되지 않은 것이다. 마치 공장에서 완성품 100개를 검사했다고 자랑해도, 같은 컨베이어 라인만 본 것이면 다른 라인의 불량을 전혀 잡지 못하는 것과 같다. 어느 부분이 얼마나 실행되었는지를 정량적으로 보여 줄 지표가 필요하기 때문에, 문장·분기·조건·MC/DC·경로라는 단계적 테스트 커버리지 기준이 등장했다.

## 📖 핵심 개념

테스트 커버리지(Test Coverage)는 테스트가 소스 코드의 어느 부분을 실행했는지를 측정하는 지표이다. 커버리지 기준이 엄격할수록 더 많은 테스트 케이스가 필요하며, 강도 순서는 **문장 < 분기 < 조건 < MC/DC < 경로** 순이다. 높은 커버리지가 높은 품질을 보장하지는 않지만, 테스트 충분성의 기준으로 활용된다.

**핵심 용어**

- **문장 커버리지(Statement Coverage)**: 모든 실행 가능한 문장을 최소 1회 실행 — 가장 약한 기준
- **분기 커버리지(Branch Coverage)**: 모든 조건문의 참(T)/거짓(F) 분기를 모두 실행 — Decision Coverage라고도 함
- **조건 커버리지(Condition Coverage)**: 각 조건(개별 Boolean 표현식)이 T/F를 모두 취하도록 실행
- **MC/DC(Modified Condition/Decision Coverage)**: 각 개별 조건이 독립적으로 결정(Decision)에 영향을 미치는 경우를 테스트 — 항공 소프트웨어 표준(DO-178C)에서 요구
- **경로 커버리지(Path Coverage)**: 모든 가능한 실행 경로를 실행 — 가장 강한 기준이나 경우의 수 폭발로 실현 불가능한 경우 多

## ✅ 이해 확인

1. 커버리지 강도 순서(약 → 강)를 나열하면?
   <details><summary>정답</summary>**문장 < 분기(결정) < 조건 < MC/DC < 경로**. 경로 커버리지가 가장 강하지만 경우의 수 폭발로 실현 불가능한 경우가 많다.</details>
2. `if (A && B)`에서 **분기 커버리지**를 만족시키는 최소 테스트 케이스 수와 예시는?
   <details><summary>정답</summary>최소 2개 — 예: (A=T, B=T)로 조건식 T 분기, (A=F, B=*) 또는 (A=T, B=F)로 조건식 F 분기를 실행하면 된다. 전체 조건식의 T/F만 다루면 되므로 개별 조건의 모든 조합은 필요 없다.</details>
3. **MC/DC**가 **조건 커버리지**보다 엄격한 이유는 무엇이며, 어떤 분야에서 요구되는가?
   <details><summary>정답</summary>MC/DC는 각 개별 조건이 **독립적으로** 결정 결과를 바꾼다는 것을 보여야 하므로, 단순히 각 조건의 T/F를 실행하는 조건 커버리지보다 강하다. 항공 소프트웨어 표준 **DO-178C**에서 요구된다.</details>

## 🎯 시험 응용

> **2025-2회**: `if (A && B)` 조건에서 분기 커버리지와 조건 커버리지의 테스트 케이스 수 비교 문제 출제. 분기 커버리지는 전체 조건식의 T/F → 최소 2개(예: A=T,B=T / A=F,B=F). 조건 커버리지는 개별 조건 A, B 각각 T/F → 최소 2개이나 분기를 보장하지 않을 수 있음. 단락평가(Short-circuit) 시 A=F이면 B 미평가. > **2025-3회**: 조건 커버리지 정의와 분기 커버리지의 차이점 서술 문제 출제. > 분기 커버리지는 **조건식 전체**의 T/F를 다루고, 조건 커버리지는 **개별 조건**의 T/F를 다룬다는 차이를 반드시 구분할 것. > MC/DC는 분기+조건 커버리지를 만족하면서 조건 간 독립성까지 보장한다.
