# 테스트 커버리지 (문장, 분기, 조건, MC/DC, 경로)

> 🔥 **매회 출제** (priority 3)

![[mt-testing-003.svg]]

## 🌱 왜 배우나

"테스트를 100개 돌렸다"고 해서 품질이 보장되는 것은 아니다. 100개의 테스트가 실제로는 같은 코드 몇 줄만 반복 실행했다면, 나머지 코드는 한 번도 검증되지 않은 것이다. 공장 비유로 말하면, 완성품 100개를 검사했지만 같은 생산 라인 제품만 봤다면, 다른 라인의 불량은 전혀 잡지 못한 것과 같다. "코드의 어느 부분이 얼마나 실행되었는지"를 숫자로 보여 주는 지표가 필요하고, 그 지표가 테스트 커버리지(Test Coverage)다.

## 📖 핵심 개념

테스트 커버리지란 "테스트가 소스 코드의 어느 부분을 실행했는지"를 백분율로 나타내는 지표다. 쉽게 말하면 "전체 코드 중 테스트로 확인된 비율"이다. 커버리지 기준은 5단계가 있고, 위로 갈수록 더 엄격하다. 문장(모든 줄 실행) → 분기(모든 if의 참/거짓 실행) → 조건(if 안 개별 조건의 참/거짓 실행) → MC/DC(각 조건이 독립적으로 결과에 영향) → 경로(모든 가능한 실행 순서 실행). 엄격할수록 더 많은 테스트 케이스(테스트 입력값과 예상 결과의 조합)가 필요하다. 높은 커버리지가 높은 품질을 반드시 보장하지는 않지만, 테스트가 충분한지 판단하는 기준으로 쓰인다.

## 🔍 시각화

```
 커버리지 강도 (약 → 강)

  문장     분기      조건     MC/DC    경로
  ─●────────●────────●────────●────────●──→ 강도
  (약)                                 (강)

  예시 코드: if (A && B) { ... }

  [문장 커버리지]  코드 줄이 1번이라도 실행되면 OK
  [분기 커버리지]  전체 조건식(A&&B)의 참/거짓 모두 실행
  [조건 커버리지]  A의 참/거짓 + B의 참/거짓 각각 실행
  [MC/DC]         각 조건(A, B)이 단독으로 결과를 바꾸는 케이스 실행
  [경로 커버리지]  가능한 모든 실행 경로 실행 (경우의 수 폭발 주의)
```

## ↔️ 이웃 개념 구분

- **분기 커버리지 vs 조건 커버리지**: 분기 커버리지는 `if (A && B)` 전체 조건식이 참인 경우와 거짓인 경우를 모두 실행하는 것. 조건 커버리지는 조건식 안의 개별 변수 A와 B가 각각 참/거짓을 모두 갖도록 실행하는 것. 조건 커버리지를 만족해도 전체 조건식의 참/거짓이 모두 나오지 않을 수 있다.
- **MC/DC vs 경로 커버리지**: MC/DC는 각 조건이 독립적으로 결과를 바꾸는지 확인(현실적으로 가능). 경로 커버리지는 모든 가능한 실행 경로를 다 실행해야 하므로 경우의 수가 폭발적으로 늘어나 현실적으로 불가능한 경우가 많다.

**핵심 용어**

- **문장 커버리지 (Statement Coverage)**: 실행 가능한 모든 코드 줄(문장)을 최소 1회 실행하는 기준. 가장 약한 커버리지
- **분기 커버리지 (Branch Coverage, Decision Coverage — 결정 커버리지)**: 모든 조건문(if, switch 등)의 참(True) 분기와 거짓(False) 분기를 모두 실행하는 기준
- **조건 커버리지 (Condition Coverage)**: 조건식을 이루는 개별 조건(Boolean 표현식) 각각이 참/거짓을 모두 취하도록 실행하는 기준. 주의: 분기 커버리지를 반드시 포함하지 않는다
- **MC/DC (Modified Condition/Decision Coverage, 변경 조건/결정 커버리지)**: 각 개별 조건이 독립적으로 전체 결정(Decision) 결과를 바꾸는 것을 증명하는 기준. 항공 소프트웨어 표준 DO-178C에서 요구
- **경로 커버리지 (Path Coverage)**: 프로그램의 모든 가능한 실행 경로를 실행하는 기준. 가장 강력하지만, 반복문(루프)이 포함되면 경우의 수가 무한에 가까워져 현실적으로 달성 불가능한 경우가 많다

## ✅ 스스로 가르쳐보기

"`if (A && B)`라는 코드가 있을 때, 분기 커버리지와 조건 커버리지를 각각 만족시키려면 어떤 테스트 케이스가 필요한지 친구에게 설명해 보세요."

체크포인트:
- 커버리지 강도 순서(문장 < 분기 < 조건 < MC/DC < 경로)를 빈칸 없이 나열할 수 있는가?
- 분기 커버리지가 "전체 조건식"의 참/거짓을, 조건 커버리지가 "개별 조건"의 참/거짓을 다룬다는 차이를 말할 수 있는가?
- MC/DC가 어떤 산업 분야에서 요구되는지 말할 수 있는가?

## 🎯 시험 응용

> **2025-2회**: `if (A && B)` 조건에서 분기 커버리지와 조건 커버리지의 테스트 케이스 수 비교 문제 출제. 분기 커버리지는 전체 조건식의 T/F → 최소 2개(예: A=T,B=T / A=F,B=F). 조건 커버리지는 개별 조건 A, B 각각 T/F → 최소 2개이나 분기를 보장하지 않을 수 있음. 단락평가(Short-circuit) 시 A=F이면 B 미평가. > **2025-3회**: 조건 커버리지 정의와 분기 커버리지의 차이점 서술 문제 출제. > 분기 커버리지는 **조건식 전체**의 T/F를 다루고, 조건 커버리지는 **개별 조건**의 T/F를 다룬다는 차이를 반드시 구분할 것. > MC/DC는 분기+조건 커버리지를 만족하면서 조건 간 독립성까지 보장한다.
